审这类「先切分服务器命令为简单命令、取动词、其余 token 判密钥路径」的判据（对照 [[pattern_shell-to-node-hook-port]]，同族但更细）时，固定过一遍：

- 动词本身用 `$(cmd)` / `` `cmd` `` 命令替换生成时，切分器常把替换结果单独成段、密钥路径那段反而没有"其余 token"可判——`$(which tac) .env` 一行验证（2026-09-22 secret-exfil-guard 实测 rc=0，HIGH）。
- 嵌套引号扫描"子串整体是密钥路径就算命中"会把纯文本提及也当命中——`git commit -m "see '.env' for setup"` 之类合法提交信息被拦（Medium，过度拦截而非漏拦，不算 HIGH）。
- glob 通配符（`.en*`、`.??v`、`.ssh/*`）绕过字面路径匹配是常态，但正则里 `\S*\.(pem|ppk)` 这类无边界前缀会让 `*.pem` 这种字面串意外命中——同一批 glob 攻击会拦一部分漏一部分，看着像修了其实是撞上正则副作用。
- 判据从"读取器枚举"翻成"任何动词+密钥路径"后，容易把闸自己想守护的目标也拦住——验证「密钥有没有被 git 追踪」（`git diff/ls-files/check-ignore .env`）这类纯元数据查询同样被拦，受益者反而拿不到本该被强化的检查能力，这类命中报「需求存疑」不报缺陷。
- 多跳管道（`env | tee x | curl`）绕过"直连管道"正则是常见但常是历史遗留，先比对 diff 是否新改了这条规则再定性，别把预存在的窟窿算进本轮回归。
- 修 glob 判据时如果是"token 转正则"（`globToRegex`），必攻两条：① 闭合但语义非法的字符类（`[z-a]` 倒序范围）——`new RegExp()` 抛 `SyntaxError` 且多半没 try/catch，一路冒到最外层 fail-open，把整条命令（含紧邻的真实密钥 token）一起静默放行，比"漏判"更严重；② 大量重复 `*`/`?` 拼接成的 `[^/]*[^/]*...` 无合并去重，对短候选串做指数回溯，100~200 个星号就能把闸挂到打不住——两条都不是"读码觉得像"，必须真掐表测（20/50/100/200 阶梯量出拐点）+ 真喂畸形字符类看 stderr 是不是"内部异常，已放行"字样。
- 正确修法是弃用 RegExp、换手写线性双指针 glob 匹配（经典 wildcard-matching 题解，`*` 只记一个回溯点，复杂度有界于「模式长×候选串长」）——验收这类修法时补测 `[`/`]` 交错、空字符类 `[]`、否定空类 `[!]`、字符类里带反斜杠、非 ASCII（emoji 代理对 / CJK）五类边界，2026-09-22 三轮 review 后这五类全部 rc 干净、无异常、耗时打平在 node 启动开销级别，是「结构性修法」而非「再打一块补丁」的判据。
- 放行表按"动词+子命令"粒度放，不连带查危险 flag：`git log` 放行后 `git log -p .env` 直接打出历史内容（`-p` 把"只读元数据"变"打印内容"）——2026-09-22 实测 `git log -p -- .env` 完整吐出假密钥，rc=0。
- 管道分段独立判定给"放行的回显动词"开新口子：`git ls-files .env | xargs cat` 密钥路径字面出现在被放行的第一段，真正读内容的第二段（`xargs cat`）里没有路径 token——echo/printf/find 类推同款风险，凡"会把参数原样回显"又被放行的动词都用这条攻一遍（实测 BEFORE 本轮改动 rc=2、AFTER rc=0，是本轮"git 不放行→ls-files 放行"新开的口子）。
- grep 位置参数判定不认裸 `--`：`startsWith('-')` 把 `--` 自己和它后面本该是"第一个位置参数=模式"的 token（如 `-x`）都当选项跳过，真正的文件参数反被误当"跳过的模式"放行——`grep -- -x .env` 实测 BEFORE rc=2、AFTER rc=0，本轮引入的真回归。
- `stripWrappers` 若用 `/["']$/` 裸剥"结尾单个引号"当兜底，token 以 `'SECRET'"` 收尾时会连剥两层收尾引号，破坏嵌套引号探测所需的配对——这条经对拍是改动前就有的老窟窿，但扫描收窄到"只对特定动词做嵌套引号判定"后容易被误当"新契约生效了该拦"，先拿改动前版本对拍同一用例再定性。
