文档 linter 一旦引入「某段之内规则放宽」的免检区，缺陷全长在**区间边界**上，不在规则本身。四条一定要攻：

1. **段名 `includes` 匹配 → 诱饵段抢锚点**。`sections.find(s => s.title.includes(label))` 取第一个命中。造一个 `## 待定问题的填法说明` 放在真段之前：真段的破行漏报、真段标题反被判成占位残留、诱饵里的示例表被误报。同一根因照打 `优先级栈` / `维度总表` / `信息架构`。
2. **末段 `to = lines.length` 吞掉整条尾巴**。免检段若是文档最后一个 `##`，`to` 默认到 EOF，其后任意多个 `###` 全进免检区——一行标题即绕过整台闸。对照法：同样三行残渣放段内 rc 0 / 挪到段外 4 条 error。
3. **免检区宽窄两份实现不一致**。同一条规则写两遍（harness 一份、零依赖脚本一份）时，免检的**范围**几乎必然错开：一份只跳「标记扫描」、另一份连「尖括号残渣」一起跳。攻法：同一份文件同时喂两个闸，比 rc。
4. **段名/列名对着测试夹具取，不是对着真模板取**。夹具写 `## 维度总表`，skill 发布的模板写 `## 2. 十二维总表`——`includes` 不命中，闸在真实产物上恒不触发，而套件全绿。**审这类闸第一件事：把 skill 的 templates/ 和 examples/ 拷成真文件名喂进去跑**，别信夹具。

**免检区的对照必须只动位置、不动结构**。第 2 条的对照做错过一次：用「插入一个重复的 `## 待定问题` 标题」来把残渣挤出免检区，结果测的是第 1 条（重复标题）不是第 2 条，还多报一条不存在的 error。正确对照是同样几行残渣分别放进免检段和另一个普通段，**其余字节完全相同**：实测 0 条 vs 3 条才算数。

**并行 agent 会在审查期间改被审文件**。本仓 tester / implementer 常与审查同时在跑，工作树随时变。2026-09-09 那次：`## 2. 十二维总表` 在我读完到我交报告之间被改成 `## 2. 维度总表（十三维）`，一条 HIGH 就此蒸发；测试脚本也在中途长出 P25-P27/U6-U7。**每条结论出口前对当前文件重跑一遍**，别交出针对已消失版本的缺陷；套件也要重跑，第一次的 25/0 是旧版本的。

**Why:** 2026-09-09 审 predev-lint.mjs + spec.mjs 待定问题段，四条攻法命中三条，另一条因文件被并行改动而作废；同一轮里我自己错过一次对照、险些交出错误 HIGH。
**How to apply:** 见到「某段内不查」「豁免」「skip(i)」「inXxx(i)」就按这四条列攻击清单；第 4 条顺手做模板 dogfood，成本一次 mktemp；交付前重跑一遍全部复现命令。

2026-09-10 复审同一批（predev-lint 与 spec.mjs 各写一份同规则）时，第 3 条换了两个新落点，都要单独造：

5. **同一条归一化规则抄成两份，正则会少一个字符**。spec.mjs 的 `SECTION_NUMBER_RE` 是 `[.、)]?`，
   predev-lint 的 `normTitle` 是 `[.、]?`——少了 `)`。单独看两边都「有精确优先」，喂同一份带诱饵段
   且真段写成 `## 1) 待定问题` 的文件，两把尺子锚到**不同的段**、报出**不相交**的行号
   （spec-lint 报诱饵的 22/24，predev-lint 反过来报真段标题 26）。查检：把两份实现的正则并排 diff，
   逐个字符对；再造一份同时触发两边的夹具做 side-by-side，比行号不比 rc。
6. **免检区的「跳过粒度」也是宽窄的一种**：一份对表行返回「整行跳过」，另一份只跳「那个词」。
   predev-lint 的 skip 是三态（true / 'pending' / false），表行拿到 true，于是待定表行里的
   `<占位>` 一个字都不报；spec.mjs 把 `placeholderBrackets` 放在 pending 分支**之前**，照报。
   同一份合法五格行：predev-lint rc 0、spec-lint rc 1。查检：免检区里逐类残渣各造一条
   （尖括号 / TBD / 待补 / 待定），分别放表行与非表行，两把尺子各跑一遍列成 2×4 表。
   **修一遍只会把宽窄对调，不会自动收敛**：2026-09-10 那批修完，predev-lint 改成表行只豁免「待定」
   （合决策），spec.mjs 却把整行 `continue` 掉——现在轮到 spec-lint 对待定表行里的 `待补` / `TBD:`
   一声不吭。所以复审时那张 2×4 表要**重新跑**，别拿上一轮的方向当结论。

7. **模板里的「示例行」才是 dogfood 的靶子，不是模板的骨架**。`<([^<>\n]{1,200})>` 会跨单元格
   把 `| 数据量 <10 万行 | 单表 >100 万行 |` 吃成一个占位——arch 模板 §9 押后决定的示例行原样中招。
   凡是「尖括号=模板残渣」的规则，先拿 `<数字` 与 `>数字` 同行的阈值表打一遍；成功判据 / 维度总表 /
   押后决定三处最容易写成这形状。

2026-09-10 第四轮复审（第五批修完）又中两条，都不是新规则的锅，是**新规则的豁免开得太宽**：

8. **「像比较式就放过」的豁免，按首字符判 = 把整类槽位放走**。两把尺子都改成
   「跳过空白看首字符是不是数字 / `=` / `-`」来放过 `<1s` 这类阈值。可模板槽位的
   说明文字**天然以数字开头**：product-spec 模板 §应用场景 的
   `<2-3 个真实发生过的案例，不写「一般来说」。…>` 原样留着，predev rc 0 / spec-lint ok:true。
   量法（把误报漏报都量出来）：枚举九份真文档（4 模板 + 5 范例）里全部 `<…>` 跨度，
   分「被豁免」与「被报出」两桶——本轮 **豁免 1 条、报出 39 条，而那唯一被豁免的就是假阴**，
   语料里根本不存在需要这条豁免的真阈值。豁免规则的验收标准是「它在真语料上救过谁」，
   救不到人只放跑人，就是净负。

9. **同一条归一化正则的字符集，第二轮还会少字符**（第 5 条的复发）。上轮 spec.mjs 的
   `SECTION_NUMBER_RE` 少了 `)`，修完这轮少的是全角 `）` 与 `．`：predev 是 `[.、．)）]?`，
   spec.mjs 是 `[.、)]?`。中文 IME 默认出全角，`## 1）待定问题` 就够。
   后果是**同一份合法文档，两把尺子报出不相交的行号**（predev [22,23,29] / spec-lint [23,24,28,29]），
   且写进签字门的那把出的是**假红**——它把待定问题段自己的标题和段内合法的「待定」行判成未完成标记。
   固定实验（比修更省事）：把编号写法做成参数扫一遍 `1. / 1、/ 1．/ 1）/ 1) `，
   两把尺子各跑一遍**比行号集合**，不比 rc；本轮五种里两种不一致。
   **两把尺子的一致性没有任何测试盯着**——10 次突变里两侧各自的断言全都响，唯独跨尺子对拍是空的。

十次突变全 CAUGHT 是好消息，说明第五批修在根因、没靠放宽断言：
M1 比较式豁免 / M2 `isSepCell` / M3 表行三态 / M4a 括注保留 / M4b 八段整词 / M4c 反引号 /
M6 predev 精确优先 / M7 spec 精确优先 / M8 spec 比较式 / M9 spec 表行三态，逐个改回旧写法，
predev 套件或 selftest 必红。**但突变全绿 ≠ 无缺陷**：这轮两条命中全落在「测试夹具与实现共享同一盲点」
——夹具用 `<1s | concurrency>`、`## 1. 待定问题`，就永远照不出数字开头的槽位和全角编号。

10. **围栏免检会吞掉一份文档的主填槽区**。DESIGN.md 模板 79 个 `{{…}}` 里 76 个在 CSS 围栏内，
    「围栏不扫」是明写的口径，于是闸只点名 3 个；把 `border-radius: {{px}};` 塞进已填范例的围栏，
    predev rc 仍是 0。原样拷模板还是 rc 1（靠 MISSING_TOKEN 那几条兜住），所以套件绿、口径也自洽，
    但半填的设计稿能签字过闸。查检：对每份文档算「免检区内槽数 / 全文槽数」，比值一高就去问
    「这份文档的填槽工作主要发生在哪」——落在免检区里就报「需求存疑」而不是缺陷，口径是用户定的。

11. **围栏免检的第二种吞尾：未闭合围栏到 EOF**（第 2 条「末段 to=EOF」的同族，2026-09-10 第七轮实测）。
    `inFence = !inFence` 的奇偶开关碰上只开不关的围栏，其后每一行都算「围栏内」。在合法且 rc 0 的
    真范例 Product-Spec 末尾追加两行（一行 ``` + 一行 `<还没定的模块>，TBD: 明天补，待补，待定。`）
    → rc 0 / 0 findings；同样那行不加围栏 → rc 1 / 4 findings。**一行反引号即豁免整条尾巴。**
    中段插不奏效（其后的 `##` 不再入 sections，MISSING_SECTION 会吵），所以专挑最后一个必需段之后追加；
    DESIGN.md 没有必需段检查，插哪儿都静。查检：凡「围栏内不扫」的闸，都造一份奇数个围栏标记的文档。

12. **「围栏内也扫槽」这类收严会反向长出误报，靶子是别人的模板语法**。DESIGN.md 打开
    `slotsInFences` 后，围栏里写 `<button>{{ label }}</button>`（Vue / Handlebars / Jinja 的插值）
    照报 PLACEHOLDER，rc 1 卡签字。当前模板与范例的围栏只有 markdown / yaml / css，语料上零误报，
    所以是隐患不是现症。收严规则的验收要跟豁免规则一样两边量：救到谁（79 条槽一条不漏）、误伤谁。

2026-09-10 第八轮（第九批「围栏内按用途扫槽」修完）复审，分叉从「扫不扫」挪到了「怎么扫」：

13. **围栏内剥不剥行内反引号，是新的宽窄分叉，而且两套契约都瞎**。predev 对围栏行照跑 stripCode
    （predev-lint.mjs:187 在 fence 分支之前），spec.mjs 围栏行拿原始行匹配（spec.mjs:363）。
    同一份 Product-Spec 的普通围栏里写 `` `{{px}}` `` → predev rc 0 / spec-lint ok:false。
    两边各做一次「向对方看齐」的突变（predev 改成不剥 / spec 改成剥），64/0 与 307 **全绿**——
    没有任何断言站在这条线上。查检：凡「剥反引号」与「围栏免检」同处一个扫描器，就把
    `` `{{槽}}` `` 分别放进围栏与正文各跑一遍两把尺子。后果不止分叉：spec.mjs 只管 Product-Spec，
    另外四份文档 predev 是唯一的尺子，于是反引号一包就是**真假绿**（拿 rc 0 的 Design-Brief 范例
    追加一个围栏含 `` `{{品牌主色}}` `` → rc 0；去掉反引号 → rc 1 两条）。
14. **闭栏行归属也是两套答案**：predev 用 fenceOpen 把闭栏行整行排除（predev-lint.mjs:172），
    spec.mjs 没有 fenceOpen、闭栏行按围栏内容照扫 → ```{{lang}} 落在闭栏位时 predev 静、spec 报。
    spec 侧没法单独突变（无 fenceOpen，一改就连开栏行一起关，撞上开栏行那条 lane 变成假 CAUGHT），
    只能靠夹具对拍照出来——**突变改不动的判断，必须换成差分夹具**，别把假 CAUGHT 当有覆盖。
15. **围栏解析是两把尺子共享的近似实现，与 CommonMark 有三处出入**（两边一致，所以是共有假红、
    不是分叉）：`~~~` 里嵌 ``` 翻掉奇偶（假 UNCLOSED_FENCE 且其后归属全错）、4 反引号围栏被内层
    ``` 提前闭合（栏内示例被误报）、缩进 4 空格（列表内）的围栏不认。值不值得修先量语料：
    9 份真文档里 `~~~` / ```` / indent4 计数全 0。
16. **跨尺子比较器已经有了（test-predev-lint.sh:67 `sfall`），却只挂在编号写法那两条 lane 上**。
    新加一整类规则（围栏）时不往比较器里挂一条，分叉照旧无人看守。加规则时问一句：进 sfall 了吗。
