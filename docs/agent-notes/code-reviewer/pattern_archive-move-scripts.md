搬迁 / 归档 / 迁移类脚本（把条目从 A 文件挪到 B 文件）按这几条攻，每条都能一条命令复现：

- **区块标题「按前缀认 + 先出现者赢」必被诱饵劫走**：在真区块**之前**插一个同前缀标题（`## Decisions（历史索引）` / `## TODO 归档说明`）。两种结果都要试：诱饵空 → 全组 moved=0、ok=true、rc=0，静默零搬迁；诱饵自带够多条目 → 从诱饵里搬、指针也写进诱饵，真区块一条没动。都不丢数据，所以不是 HIGH，但归档从此永不触发——报 MEDIUM 并要求「标题精确认 + 同 kind 命中多个时出 note」。
- **判重口径 ≠ 核对口径 = 永久卡死**：判重用「整条文本连续子串」而核对用「整行集合」时，归档里只要有一条以本条目为前缀的更长行，就被判成「已归档」不插入 → 第 3 步逐行核对必失配 → 整批 rc=1、每次重跑同样卡住。造法：归档里放 `- <条目原文> 后来补的尾巴`。方向是安全失败（正文一字节不动），但要人工解开。
- **零丢失要用 node 精确整行核，别用 grep**：`grep -qxF "$l"` 会把以 `-` 开头的条目行当选项吃掉（要 `--`），结果假报 62 条 LOST。正确做法：读 orig / 正文 / 归档三份，每条原始条目行断言「在正文 或 在归档」。
- **「被杀在两次写之间」用状态等价模拟，不用真杀**：跑一遍 → 把正文拷回原样（= 归档已写、正文未写）→ 再跑，断言 alreadyArchived 计满、归档条目数不翻倍、指针累计不重复加。
- **两份归一实现只对齐一半**：修 CRLF 时同步改了重签命令，但重签命令没跟着剥 BOM / 没跟着别的前处理。验法：造一个带 BOM 的文件，把扫描器的前处理手写一遍，两边对 line1 算 sha256 比一比。
- **`--root <dir>` 后面紧跟另一个开关**：`--root --check` 会把 `--check` 当目录值吞掉并静默进写模式，不报用法错。
- **文档和脚本的插入位置常相反**：脚本「插在目标段第一条现有条目之前」，文档写「追加到现有内容之后」。查 C 类一致性时除了数字，必查插入位置、指针行文案、指针写给哪些区块。
