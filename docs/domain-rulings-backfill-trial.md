# 口径库栏位回填试验（2026-09-11）

目的不是产出 8 条口径，是**验栏位设计对不对**。素材取自 digifiber 项目 `Product-Spec-CHANGELOG.md` 里已经手写好的 `### 口径` / `### 硬约束` 段（11 个段落、36 条 bullet），原样回填，不改写内容。

栏位来自两处：progress.md 的 Decisions 三要素（依据 / 适用范围 / 取代），加上 mango-memory `docs/v3/AGING-MODEL.md` 四维度老化模型里可借的三维（条件失效 / 关联失效 / 批量失效，频率衰减不借——口径不因少被引用而降权）。

## 回填样张

### R-OLT-001 OLT 关联键用 IP 不用名
- **现行值**：OLT 关联键固定为 OLT IP 字段；禁止用 OLT 名。
- **依据**：`pon_links.source_name` 形如 `<IP>/0/frame/port`；客户名单与网管命名普遍存在变体。
- **适用范围**：凡按 OLT 聚合的查询与展示（OLT 专题评估、端到端 TOPO）。
- **取代**：无
- **失效条件**：网管与客户名单的 OLT 命名统一到同一套规范后需重评。〔源文未写，据依据推出〕
- **来源**：CHANGELOG v2.45（2026-08-27，用户已签字）

### R-ONU-001 ONU 归盒走直接边逐 ONU 定位
- **现行值**：用 `PON SEGMENT` 的 `Splitter→ONU` **直接边**逐 ONU 定位；禁止取「整个 PON 口最深分光器所在盒」，禁止最深分光器堆叠。
- **依据**：〔源文未给〕
- **适用范围**：ONU 归盒；与 TOPO 红锁① 同一口径。
- **取代**：无（v2.45.1 复述同一口径，非修订）
- **失效条件**：〔未知〕
- **来源**：CHANGELOG v2.45 + v2.45.1（2026-08-27 / 08-31）

### R-GEO-001 线型语言三分
- **现行值**：实线＝真实光缆路由几何；琥珀虚线＝飞线；灰虚线＝OLT→首盒网管逻辑映射。缺几何的段**不得**两点直连伪造。
- **依据**：实测全库 0 条 `cable_segments` 接触 OLT。
- **适用范围**：所有地图图层的线要素渲染。
- **取代**：无
- **失效条件**：`cable_segments` 出现接触 OLT 的记录时，灰虚线的存在理由消失，需重定。
- **来源**：CHANGELOG v2.45 硬约束（2026-08-27）

### R-OPT-001 光功率只有「功率不合格」计为光功率问题
- **现行值**：实测与下游共享分列；「存疑/不合格」按 `retest_reason` 再拆，**只有 `功率不合格`** 计为光功率问题；任何场合不得用 `needs_retest` 总数表述光功率不合格。
- **依据**：〔源文未给，但禁令措辞说明曾发生过误用〕
- **适用范围**：所有涉及光功率的统计、卡片、导出。
- **取代**：无
- **失效条件**：`retest_reason` 的取值集合变化时需重核。
- **来源**：CHANGELOG v2.45 硬约束（2026-08-27）

### R-CLU-001 Cluster 归属取最内层
- **现行值**：Cluster 归属＝最内层优先（面积最小者），多归属如实披露。
- **依据**：〔源文未给〕
- **适用范围**：Cluster 归属判定。
- **取代**：无
- **失效条件**：**关联失效**——受 R-CLU-002（边界算法）保护；边界算法一变，本条须连带复核。
- **来源**：CHANGELOG v2.45（2026-08-27）

### R-CLU-002 Cluster 边界＝整簇凸包且不可退化
- **现行值**：Cluster 边界为整簇凸包，不可退化。
- **依据**：〔源文在 v2.44，本次未取〕
- **适用范围**：所有 Cluster 边界生成与判定。
- **取代**：v2.35 的「FAT 外轮廓」，更早为 v2.31 的「凹包外轮廓」——**同一条口径的第三版**。
- **失效条件**：受 progress.md Pinned 2026-08-26 保护，改动需用户拍板。
- **被谁依赖**：R-CLU-001、覆盖健康、责任区划分、整改单导出。
- **来源**：CHANGELOG v2.44（2026-08-26，用户拍板）

### R-ADC-001 token 过期即停并转人工，禁自动重登
- **现行值**：ADC token ~2h 过期、重登需 GUI（`relogin.mjs`，headless 不可行）；**不实现自动重登**。过期即告警＋暂停本次下载＋看板标「待人工补登」；人工补 `ADC_AUTH_FILE` 后下次调度自动恢复。禁止静默成功／无限重试／半下载刷新业务库。
- **依据**：token 有效期约 2 小时；重登流程依赖 GUI，headless 环境跑不通（实测）。
- **适用范围**：ADC 远端同步。
- **取代**：无
- **失效条件**：ADC 提供可 headless 的认证方式时，「不自动重登」的前提消失。
- **来源**：CHANGELOG v2.34（2026-08-12）

### R-TOPO-001 ONU 叶子只有真断才标红
- **现行值**：ONU 叶子仅 `onu_chain_summary.connectivity='broken'` 时标红并附断点根因；`full` / `preconnect` / 固化值 NULL 一律不标。
- **依据**：旧实现每叶子跑 PON 全链递归、全链不通即红，是 v1.28 改判前的残留；且每叶一次递归 CTE，OLT 整树数百叶子时开销大。
- **适用范围**：TOPO 视图的 ONU 叶子着色。
- **取代**：v1.28 之前的「全链不通即红」。
- **失效条件**：〔无〕
- **已知污染**：生产 session3 的 `onu_chain_summary.connectivity` 74,586 行全 NULL（Phase 39 代码已合并但该 session 未重算），重算前 ONU 叶子全显 normal。
- **来源**：CHANGELOG v1.35（2026-07-16）

## 栏位验证结论

**填得满的三栏**——现行值、适用范围、来源。8 条全部无需推断，直接从源文抄。**现行值这一栏尤其顺**：源文本来就是判据式写法（「固定为 X，禁止 Y」），不是叙述式，直接可用。

**依据栏：4/8 满**。填得满的那几条含金量最高——「实测全库 0 条 `cable_segments` 接触 OLT」「74,586 行全 NULL」「headless 不可行」都是现场证据，AI 拿到能自己去复查。填不满的四条里，R-OPT-001 的禁令措辞（「任何场合不得」）说明背后有过事故，但事故本身没写下来。**这一栏的缺口就是知识流失的位置。**

**取代栏：2/8 有值，但源文已经在用自然语言表达**。v2.34 写「修订 v2.13『CLI 合同』」，v1.35 写「v1.28 改判前旧口径残留」，v2.45.1 写「与 TOPO 红锁①同一口径」。关系本来就在，只是散在句子里、机器读不到。**这一栏不是新增负担，是把已有的东西挪到固定位置。**

**失效条件栏：1/8 源文明写，5/8 可从依据推出，2/8 推不出**。这是最缺的一栏，也是最该补的——R-GEO-001 的灰虚线只因为「全库 0 条接触 OLT」才成立，哪天有了就该重定，但源文没写这句。

**回填时冒出来两栏是我原设计没有的**：

R-CLU-002 需要「**被谁依赖**」——边界算法被四处引用，改它要连带复核。这是老化模型里 `related_superseded` 的正向表达，比只写「取代」更有用。

R-TOPO-001 需要「**已知污染**」——口径本身对，但生产数据不满足前提（74,586 行 NULL）。这不是失效，是「暂时不成立」。混进失效条件里会误导。

**一个必须先做的分拣**：36 条 bullet 里混着两类。「不新建持久表、不新增依赖、不改写权威数据」是本次范围限制，做完即失效，**不该进口径库**；「线型语言三分」是永久领域真相。不先分拣，库里一半是过期噪音。粗看 36 条里约 1/3 是范围限制。

**结论**：五栏改七栏——现行值 / 依据 / 适用范围 / 取代 / 失效条件 / 被谁依赖 / 已知污染。后两栏是回填逼出来的，不是设计出来的。
