# 领域界面标签禁止生造术语/缩写

**问题描述**：2026-08-05 做 T6497 机房施工连接指导图时，在光缆段标签上生造了「N芯通 / M芯↓盒」这个缩写词（build_room_guides.py:649），随后被 DEMO 和主系统③馈线全景沿用。2026-08-06 用户（ODN 领域资深从业者）连续两次表示看不懂：「我是听不懂，我是ODN领域搞了这么久，我都听不懂」。

**触发场景**：为领域工具（ODN/光纤网络）生成界面标签、图例、状态文案时，需要给某种状态/实体起名，领域里有现成说法（直通/过路/成端/进盒）但没沿用，自己造了一个缩写再配图例释义。

**教训/建议**：
- 领域里有现成说法就必须用现成说法，不生造术语/缩写。
- 拿不准领域惯用词就先问用户，而不是自己造一个再配图例释义——图例释义救不了生造词，专家不会读。
- 举一反三：任何新上界面的词汇，先问「这词领域里本来叫什么」，禁止「自己造词+写图例解释」模式。
- 关联项：同批还发现「96芯通」数字口径瑕疵（90 熔接芯 + 6 进盒芯被重复计成 96 通），术语改名与口径修正同批执行。
