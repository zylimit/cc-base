# 质量看板只暴露问题，不分派责任方、不安排流程、不给整改意见

**问题描述**：
- 10-22 第一次：主 Agent 给质量看板每类问题加「谁去改」，用户纠正：「你不用管谁去改，我就抛出具体问题，给一下，让他们自己去派活，我不管，不帮他们安排，就暴露问题，但是要逻辑自洽」。主 Agent 只去掉了「谁去改」，保留了「怎么改」。
- 10-25 第二次（同一条踩第二次）：v2.60 每条问题仍写三段「问题 / 怎么改 / 旁证」，新做的光功率卡还在往里加改法。用户再次纠正：「怎么改去掉，不要需要说了」「专家多的是，我就报问题」「有逻辑的报问题」。

**触发场景**：
- 10-22：为质量看板每类问题补「整改意见」时顺手加了责任方归属。
- 10-25：主 Agent 把 10-22 用户「要能具体整改意见」当成必须有「怎么改」，又把「只暴露问题」只窄读成「不写谁去改」，其余整改建议照加。

**教训/建议**：
- 用户说「只暴露问题」，范围包括责任方、流程、也包括改法；只去掉其中一项等于没听全。
- 系统只报问题：每条讲清判据（凭什么算问题）和事实逻辑（哪几个事实推出这个判断），再配能支撑判断的旁证。不写「怎么改」，不写「需要……」。
- 不分派责任方，不替人判断哪边对；判断不了的如实写两边不一致，不附改成什么。
- 同一对象下的几条问题不能互相矛盾，写完按对象回读一遍。
- 用户当前表述与更早指令表面冲突时（如 10-22 的「具体整改意见」与「只暴露问题」），取最新、最窄的一句，并回头把前面已加的同类内容一并清掉，不留残余。
- 这个用户是「暴露问题」的角色，专家另有人；凡加了责任分派、流程安排、整改建议，都是自己加戏。相关旧条：domain-ui-labels-no-invented-jargon.md、issue-list-goal-is-discovery-not-lower-count-no-self-invented-filter-rules.md。
- 自检信号：想加「谁去改 / 怎么改 / 建议 / 需要 / 先后顺序」这类栏位或措辞时，先停。

**适用范围与例外**：所有质量类功能一律按此（用户明确指出适用全部）；例外未说明，用户明确要求加责任方或改法时按当前指令办。
