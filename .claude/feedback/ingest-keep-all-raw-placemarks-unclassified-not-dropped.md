# 入库全量保留原始地标，认不出的标「未分类」也存

**问题描述**：设计/竣工 KMZ 入库只存分类器认得的资产类型。认不出的地标（例如 KMZ 里现成的 Cluster 大边界 01_Boundary 层）在 asset_builder 阶段 AssetBuildSkipped 被直接丢掉，design_asset_sources 里也没有。用户一直以为全量下载就是全量入库。用户原话：「奇怪了，10-11，有病吧，为什么会漏，我要求全部都要入库，没用也放着」「现在库里应该有啊，是全量下载的」。主 Agent 起初把「库里找不到」归因到 10-11 的清理操作，是误判，真因是入库阶段丢弃。

**触发场景**：要拿 KMZ 里现成的 Cluster 边界，查库发现没有；主 Agent 先去查某次清理操作，没先查入库有没有丢弃。

**教训/建议**：
1. 入库一律全量保留原始地标；分类器认不出的标「未分类」也存，不 Skip、不丢。「没用也放着」是用户的明确要求。
2. 判断「数据缺失」时，先查入库链路有没有丢弃（分类器、builder、Skip 路径、来源表行数对原文件地标数），再去怀疑某次清理或人为操作。不凭时间点相近就归因。
3. 做任何外部数据导入，设计时就默认「全量落原始层，分类是附加标签」，不把分类器当入库的过滤器。

**适用范围与例外**：设计/竣工导入，以及以后所有外部数据导入。例外未说明；若某类数据体量大到需要裁剪，先问用户，不自行丢。
