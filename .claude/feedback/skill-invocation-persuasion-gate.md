# Skill 调用合规靠劝服工程，不靠"写清楚"

**问题描述**：
规则写成"应该先调 Skill / 建议匹配时调用"，agent 照样跳——它会自己找一套"合理"借口绕过去（"我知道这意思"、"这个很简单"、"先看看代码"），把概念当成已经用了 skill。靠"写得更清楚"补不上这个洞，因为问题不在表达清不清楚，在留没留理性化的空间。

**触发场景**：
- 往 CLAUDE.md / skill 写"匹配即调用"这类合规闸时。
- 某条规则反复被 agent 用借口绕过（自报"我懂了直接做"）。

**教训/建议**：

Why：研究（Meincke et al. 2025，约 28000 次 LLM 对话实测）——Authority + Commitment + Scarcity 组合把合规率从 33% 提到 72%；agent 是"准人类"，对劝服心理学敏感，软措辞（应该/建议）给它留了讨价还价的口子。Superpowers 的演化里 agent 反复用"我知道这意思"跳过 skill，才逼出多层强制闸（EXTREMELY-IMPORTANT 块 + 1% 即调 + 首响应前置清单 + Red Flags 黑名单）。结论：合规靠劝服工程，不靠把规则写得更详细。

How to apply：
1. **绝对命令语言**：用"必须 / 禁止 / 失败"，不用"应该 / 建议 / 最好"——后者给 agent 留理性化空间。
2. **抹掉理性化空间**：把"匹配时调用"收紧成"1% 即调，宁可多调不可漏调"，不给"这次大概不算匹配"的自我开脱余地。
3. **高频被跳的规则配前置清单 + 逃逸借口黑名单**：列出"任何回复/动作前先过"的自检步骤，再把已知借口逐条点名拦截（识破不接受）。
4. **关键闸标明后果**：用"跳过 = 失败"把代价讲死，比单纯说"要做"更挡得住。

进化信号（给 evolution-engine）：写合规类规则（Skill 调用、验收闸、red-locks 等）时统一套这套劝服工程——绝对语言 + 前置清单 + Red Flags 黑名单 + "跳过=失败"。可在 skill-builder / 各 skill 的强制环节复用本模式。
