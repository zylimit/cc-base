# 脚手架交付应复制即用且保持项目根目录清爽

**问题描述**：脚手架的交付思路偏向执行安装器，并在项目根目录暴露较多 doctor、测试、发布、能力说明等维护文件。用户质疑「一定要安装吗」，希望直接复制 `.claude/`（含 CLAUDE.md、hooks、skills、agents）到目标项目即可使用；同时明确认为根目录太乱，希望像隐藏配置目录式脚手架一样清爽。

**触发场景**：设计 cc-base 的分发方式、目标项目目录结构、setup 脚本或 release 包内容时。

**教训/建议**：把「复制即用」设为默认交付契约：核心运行资产复制到目标项目后无需额外安装步骤、常驻服务或机器级配置即可工作。安装器可以作为批量复制、升级或校验的可选便利工具，但不能成为运行前置条件。正式暴露在目标项目根目录的文件应压到最少，优先只保留确有必要的用户文档；agents、skills、hooks、模板、doctor、测试及脚手架维护资产应归入 `.claude/` 或仅留在脚手架源仓库，不把维护仓库的杂物复制进业务项目。
