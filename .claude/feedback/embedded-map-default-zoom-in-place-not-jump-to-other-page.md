# 页内嵌地图默认配原地放大，不默认配跳转

**问题描述**：规格 v2.55「放在哪」一段，主 Agent 自己定了默认——页内单独放一张地图，另放一个「到主地图上看」的跳转。起因是用户问「GIS也单独搞个？」，主 Agent 给了这个建议，标为默认、待用户看过设计稿后定。做出来后页内地图偏小，属性与图例排在右侧栏。用户实际用了才纠正：「在主地图看这个机房，意义不大，直接在本页弹出浮动放大才是正道，相关的属性和图例，在放大后的地图上悬浮呈现」。

**触发场景**：规格阶段为「要不要单独做地图」给出带默认值的建议；默认值只在设计稿层面讨论，没有到真实使用里验证，用户用过实物才暴露问题。

**教训/建议**：
- 页内嵌的小地图，默认方案配「本页原地放大」，不配「跳去别的页面」。跳走会丢掉本页刚算出来的东西和上下文（主 Agent 的理解，非用户原话）。
- 属性、图例这类要对着图看的东西，放大后浮在图上，不留在会被盖住的侧栏（用户原话已明确要求悬浮）。
- 给用户的建议若标「默认、待定」，要在交互形态上先想「用户看图时手在哪、眼睛在哪」，不只想信息放在哪个页面。
- 主 Agent 的两条推断（跳走丢上下文、对着图看的东西要浮在图上）是推断，不是用户确认的事实；是否推广到别的页面用户没说，别擅自当成全局规则。

**适用范围与例外**：本功能的地图页签按这条办。别的页面出现「页内小地图 + 跳转大地图」的设计时，把「原地放大 + 悬浮属性图例」作为首选方案提出来供用户确认，不直接当既定。例外未说明。

**本次落地**：主 Agent 已去掉「到主地图上看」的跳转，改为本页浮动放大，图例与属性悬浮在放大后的地图上；规格、变更记录、进度已同步改。skill / rule 本体未动（用户没说「以后都」）。
