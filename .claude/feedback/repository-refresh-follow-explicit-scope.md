# 仓库刷新应遵循用户明确授权，避免擅自加重流程

**问题描述**：用户已经说明本地内容可以清理、旧目录不要，并要求从指定 GitHub 仓库直接获取最新代码。主 Agent 仍采用临时克隆、内容比对和备份交换等额外流程，甚至因目录占用把临时克隆移入目标目录，直到用户连续纠正「没你啥事」「你直接取最新的」「直接拉下来就好了」才回到直接克隆。

**触发场景**：仓库初始化、重拉或刷新时，用户已经明确给出远程地址、允许清理本地内容，并明确不保留某些旧目录或资产。

**教训/建议**：先用只读检查确认目标路径与状态；用户已明确授权清理且目标目录为空时，直接执行 `git clone <repo> .` 并核验远程、分支、HEAD 和工作区状态。不要自行增加临时克隆、差异比对、备份交换或旧资产迁移；只有目标非空、存在未授权数据或克隆会覆盖不明内容时才停下说明风险。用户明确不要的旧资产不得被「保险起见」保留或迁回。
