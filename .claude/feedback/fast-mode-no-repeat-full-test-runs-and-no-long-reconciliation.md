# 快速开发模式下不重复跑全量测试，催促时不写长对账

**问题描述**：上午用户已定快速开发模式。下午连做入库并行 v2.52、清空改后台执行 v2.52.1、已上传文件清除 v2.53 三个小功能，每个功能的全量测试被跑多遍：实现者交回前一遍、主 Agent 验收亲跑一遍、提交后为给 deployer 存证再跑一遍、审查者再跑相关用例；修阻断项后同样再来一轮。测试行数也两次超过 50% 上限（一次 70% 以上、一次 52%）。用户先说「快速开发模式，很多都省了」，主 Agent 回了一大段对账说明省了什么没省什么，被打断：「不要浪费时间了」。随后主 Agent 发出「提交 + 重跑全量测试存证 + 推送」命令，被用户直接拒绝执行，并明确指示：「测试要尽可能降低，不能过度测试」。

**触发场景**：快速开发模式已定后的连续小功能迭代；代码没变，仍在验收、存证、复核三处各跑一遍全量；用户表达不耐烦时主 Agent 以长篇说明回应。

**教训/建议**：
- 同一份代码全量测试只跑一次，主 Agent 验收那次即为证据；代码没变不重跑，提交后不为存证再跑。
- 修阻断项只补直接对应的用例；审查复核只看修的那一处。
- 测试行数守住 ≤ 实现 50% 的上限，超了先压缩再交。
- 用户催促或打断时直接行动，不写长对账；要说明的事一两句带过。
- 解读（主 Agent 自己的判断，非用户原话）：用户嫌的是重复跑同一份代码的测试和长篇解释，不是嫌审查；审查当天拦下四个会毁数据的问题，用户没有要求取消，所以审查保留，不要借此推到「不审查」。

**适用范围与例外**：本项目快速开发模式下的小功能迭代按这条来。非快速模式、strict 档、HIGH 档（线上 bug / 迁移 / 安全）下是否同样压缩，用户未说明，不要自行外推；发版前按既有规则要求的亲跑全量回归是否算「重复」，也未说明，遇到时先问。

**本次落地**：progress.md Decisions 新增 2026-10-11「测试再收紧」一条，内容即上面前两条教训；之后的提交、推送、派部署都没有重跑测试。skill / rule 本体未改。落点建议：若用户后续说「以后都这样」，再把「同一份代码全量只跑一次」写进 dev-builder 快速开发模式相关段落与 dev-workflow-details 的验收/存证环节；当前先靠 Decisions 与本条生效。
