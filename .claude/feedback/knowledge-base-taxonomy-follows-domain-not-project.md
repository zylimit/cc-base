# 分类体系跟着领域本身走，不套用当前项目结构

**问题描述**：
domain-rulings 草拟的"按域分文件"隐含了一个假设——条目都该归到本项目已有的某个模块。用户纠正：域应该取自领域本身，不取自本项目的模块划分；行业规范、组织怎么办事、外部系统的脾气都可以自立一域，跟本项目关系很远但值得留的条目不该因为"归不到本项目哪个模块"就被判出库；一时归不到域的先进 `domain/_未归域.md`，攒够一类再拆出去。

**触发场景**：
设计一个"跟着领域走、不跟着仓库走"的知识库的文件组织方式时，不自觉地拿手边这个项目的目录结构当了分类模板。

**教训/建议**：
判断分类维度时先问"这条分类是从知识本身来的，还是从我现在正在做的这个项目结构抄过来的"——凡是要求知识长期有效、可能被下一个八竿子打不着的项目复用的场合，分类必须服从被描述的对象（领域），不能服从当前容器（项目/仓库）。

**适用范围与例外**：
适用于设计长期沉淀、可能跨项目复用的知识库分类维度；项目专属知识仍可按项目结构分类，不受影响。
