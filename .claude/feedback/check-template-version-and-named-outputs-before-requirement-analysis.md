# 需求分析前先核对依据：模板是不是现行正式版、点名的产出物逐个找到、旧记录不当建模依据

**问题描述**：2026-10-12 主 Agent 做新需求「传统段（馈线光缆）还原」的需求分析。用户给的需求第 3 条原文写着要生成「光缆段切芯／预连接ODN-成端」导入数据。主 Agent 拿仓库里现成的一份导入模板（`samples/ImportAddTemplate.xlsx`，2026-07-31 的版本，39 张表）直接当依据，这份里没有「光缆段切芯」这张表。主 Agent 没有追问这张表在哪，记需求时把这四个字丢掉，只写了「预连接ODN-成端」；随后照试点旧记录的录法定了一套建模（光缆在每只盒子处切成一段一段、路过的纤芯同号熔接、每只盒子一只接头盒），并做了三轮演示。直到用户问「目前3个需求你有多少把握了」，主 Agent 才回头核对，发现模板里没有这张表，问用户「我当成就是预连接ODN-成端那张表，对吗」（这句是主 Agent 的话）。用户纠正：「正式得Digifiber模板，在co目录下 ImportAddTemplate」。

主 Agent 去看正式模板：共 42 张表，有单独的「光缆段切芯」，规则写明切芯的点必须是这条光缆段路由上的一个点、导入后撤不回；成端与熔接三张表多了说明「用的是哪一截纤芯」的两列。按主 Agent 对正式模板的读法，光缆应整条不切段、在盒子处切芯，接头盒与熔接只出现在子缆接主缆的地方；先前那套建模在样板站点上会多出二十多段光缆段、二十多只不存在的接头盒、一千多条不存在的熔接，并漏掉整张切芯表。业务口径本身记在 Product-Spec.md 与 progress.md Decisions，本条只记工作方法。

**触发场景**：产出物要对接外部系统的导入格式，依据是仓库里放着的一份模板拷贝。三件事都没核对就开了工：一，需求原文点名的表名在手上的模板里找不到，这是最早、最便宜的信号，却处理成了丢掉名字；二，拿仓库里的拷贝直接当依据，没有先确认它是不是现行正式版，这份是 7 月的旧版；三，试点旧记录是别人以前的录法，被当成了建模的依据。错的依据上走完三轮演示，才由用户一句追问逼出核对，开工前主 Agent 自己没有核对。

**教训/建议**：

（以下三条为主 Agent 的解读，不是用户原话；用户的原话只有上面那一句纠正）
- 需求原文里出现的每一个产出物名字（表名、文件名）都要在手上的模板或样例里逐个找到；找不到的当场问，不许悄悄丢掉或换成别的说法。
- 外部系统的模板、接口说明这类会变的依据，开始分析前先问一句「这是不是最新的正式版」，并看文件日期；仓库里现成的拷贝不等于现行版本。
- 现有记录（别人以前录的数据）只能说明「以前是怎么录的」，不能直接当成「应该怎么建模」；两者不一致时以用户原话与正式模板为准。
