# 删除范围：人工勘测成果整类保护，先列清单再问

**问题描述**：

第一次（2026-10-21）：主 Agent 设计「DigiFiber删除表」（REQ-TRAD-011），依据用户前一句「除了跳纤治理的数据都可以删除」，把范围定为：删除旧光缆段及其纤芯、光缆段路由、纤芯-成端、纤芯-熔接、预连接ODN-成端，只把连接-跳纤排除在外。用户随即纠正：「不能删除机房勘测数据。。。」

第二次（2026-11-01）：用户要清理 T0511 机房的历史数据，原话「除了勘测数据，我们之前导入的还有很前面的数据都给他清理了」。主 Agent 刚开始只读盘点导出文件，用户就打断纠正：「不要删除勘测数据啊，哪怕是一坨屎」。

**触发场景**：
- 第一次：把用户一句口头的删除授权直接当成完整范围写进 Spec 和派单，没先问哪些数据是人工采集的。「除了跳纤」被当成唯一的例外。
- 第二次：用户已经明说「除了勘测数据」，主 Agent 仍在盘点阶段没有先按来源把勘测来源的记录分出去，眼看要把「我们之前导入的」「很前面的数据」整批当作可删对象。此外，别人用 fiber|importv2 导入、但与勘测逐条对得上的跳纤，也属于勘测成果，不能因为导入来源标记不是勘测就归入可删。用户这次的话说明态度：质量再差也保留，不以质量好坏决定删不删。

**教训/建议**：
- 用户说「除了 X 都可以删」时，X 是举例，不是完整保护清单。
- 凡是删用户方现有数据，动笔前先把「人工勘测、扫码得来的成果」整类列出来，问一句再定范围。删了收不回，靠人工采集的数据最不能删。
- 出删除清单之前必须先按来源分拣：勘测工作簿来源的记录（含别人 fiber|importv2 导入、与勘测逐条对得上的跳纤）永不进删除清单；质量差不是删的理由。
- 交付删除清单时必须写明保留了什么（按来源分类的保留项与条数），让用户一眼能核对勘测数据没被带进去。
- 本项目的具体口径：机房内的一切都是勘测成果，一律不删，包括机房内的跳纤、设备成端、局向，机房内设备（ODF 等）上的纤芯成端，以及站点、机房、机架、设备本身。删除表只放机房外的东西。
- 要删的旧缆如果在机房 ODF 上有勘测成端，这根缆不删，进问题清单。

**适用范围与例外**：任何会删用户方存量数据的设计、盘点、清理与派单都按这条来；用户自己给了逐表确认的完整清单时按清单，但勘测来源记录仍须先分拣出来核对。

**本次落地**：第二次纠正已落到 progress.md Decisions 2026-11-01「勘测数据永不删除」条，以及用户记忆 never-delete-survey-data.md；当前产物（只读盘点）尚无删除清单，后续出清单时按来源分拣并写明保留项。skill / rule 本体未动。
