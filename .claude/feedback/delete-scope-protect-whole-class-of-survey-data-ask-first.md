# 删除范围：人工勘测成果整类保护，先列清单再问

**问题描述**：主 Agent 设计「DigiFiber删除表」（REQ-TRAD-011），依据用户前一句「除了跳纤治理的数据都可以删除」，把范围定为：删除旧光缆段及其纤芯、光缆段路由、纤芯-成端、纤芯-熔接、预连接ODN-成端，只把连接-跳纤排除在外。用户随即纠正：「不能删除机房勘测数据。。。」

**触发场景**：把用户一句口头的删除授权，直接当成完整范围写进 Spec 和派单，没有先问哪些数据是人工采集的。「除了跳纤」被当成唯一的例外。

**教训/建议**：
- 用户说「除了 X 都可以删」时，X 是举例，不是完整保护清单。
- 凡是删用户方现有数据，动笔前先把「人工勘测、扫码得来的成果」整类列出来，问一句再定范围。删了收不回，靠人工采集的数据最不能删。
- 本项目的具体口径：机房内的一切都是勘测成果，一律不删，包括机房内的跳纤、设备成端、局向，机房内设备（ODF 等）上的纤芯成端，以及站点、机房、机架、设备本身。删除表只放机房外的东西。
- 要删的旧缆如果在机房 ODF 上有勘测成端，这根缆不删，进问题清单。

**适用范围与例外**：任何会删用户方存量数据的设计与派单都按这条来；用户自己给了逐表确认的完整清单时按清单。

**本次落地**：Product-Spec.md REQ-TRAD-011 与 Product-Spec-CHANGELOG.md 已改为只删机房外数据、机房 ODF 上有勘测成端的旧缆不删并进问题清单；给 implementer 的派单已同步。skill / rule 本体未动。
