# 问题说明先讲人话故事，一张图只画一件事，图用网页矢量

**问题描述**：主 Agent 给 T0511 做「矛盾手册」（给不信任数据的相关方看各份资料哪里对不上），先出 Excel，用单元格涂色画图，每条写成「ODF2 的 96 个成端挂在 1.7 米线头残段上」「跳纤和缆不在一台 ODF」这类工程术语句子。用户先说「看来做成Excel确实，还是看不清楚」，又打断说「你的描述，看不清楚，说人话」。主 Agent 改成大白话样例（「网管说……勘测说……竣工图说……三份资料拼不到一起」，用光纤 / 跳线 / 光缆 / 盒子代替成端 / 熔接 / 切芯 / 补位）后用户认可，并要求「做成网页吧」。

**触发场景**：为非技术相关方出「各份资料哪里对不上」的说明材料；首版选了 Excel 作载体，文字直接用内部术语和字段名。

**教训/建议**：
- 每条问题先讲一个人话故事：谁说了什么、哪几份资料拼不到一起，用具体的例子讲；术语、字段名、数量细节收进可展开的详情，默认不露。
- 一张图只画一件事，不把多个现象叠在同一张图里。
- Excel 格子涂色画图分辨率不够，看不清；要画图就用网页矢量图（SVG），载体直接选本地网页，不先走 Excel 再返工。
- 用户说「看不清楚」先分清是图的问题还是文字的问题，两处都要查；这次两处都有问题。
- 换词对照：成端 / 熔接 / 切芯 / 补位等内部词，面向相关方一律换成光纤、跳线、光缆、盒子这类日常说法。

**适用范围与例外**：见 frontmatter。工程师自用的字段级明细不受此限，但「先故事后明细」的顺序仍适用于给人看的页面。
