# 完成声明需当场新鲜证据：不可跳步五步闸

**问题描述**：
近期两次"凭表层信息断言 + 事后追认"翻车：
1. PS 5.1 下 git fatal 泄漏，第一次按内部记忆判定是 PSNative 设置问题、改了 PSNativeCommandUseErrorActionPreference，事后核验才发现根因不在此，撤回重修（改用 --quiet/try-catch）。
2. v1.0.1 误判远程仓库不存在、按"需新建"下结论，实际远程早有——没先查远程约束就开口。
两次共性：结论先于证据，证据是事后补的；本该当场跑一条能证明结论的命令、读完输出再开口。

**触发场景**：
任何要说出"完成 / 通过 / 修好 / 不存在 / 是 XX 根因"的出口——编码自检、bug 修复收尾、测试报绿、配置结论、部署验收、给用户的根因判断。子 Agent 回报"完成"/"通过"/空回复时尤其危险：那只反映它跑完了，不等于结果正确。

**教训/建议**：

Why：完成声明是会被下游当真的承诺（主 Agent 据此 commit、用户据此放行）。凭过期记忆或上一条消息的旧输出下结论，等于把"我记得/应该是"当成了"我刚验过"。外部工具（CLI、远程仓库、第三方服务）状态变动快，没当场核验的断言随时翻车，错了用户买单。

How to apply —— 任何完成/通过结论出口前走完不可跳步五步闸：
1. **先想清哪条命令能证明这个结论**——证明"测试过"的是测试运行器输出，不是"我改完了"。
2. **跑全量、全新的该命令**——当场重跑，不复用上一条消息的旧输出、不引用"前面跑过"。
3. **读完整输出 + 看 exit code + 数失败数**——不是输出滚过去就算，要读到底。
4. **确认输出确实支持结论**——输出有了 ≠ 支持结论；编译过不等于功能对，要对上结论再开口。
5. **才许下结论**。

禁用措辞：没跑过就下的"应该 / 大概 / 估计 / 看起来 / 之前测过了"一律不算证据。没有当场跑出的新鲜证据，不报完成。

声称 → 证据对照（充分 / 不充分）：
| 声称 | 充分证据 | 不充分（不算数） |
|------|---------|-----------------|
| 测试通过 | 当场跑测试命令、输出 0 failures + 通过计数 | "之前跑过" / "应该过" / 只跑了改动相关没跑全量 |
| bug 修好 | 锁定原始症状的失败测试当场转绿（红→绿） | 改了代码就假设好了 / 没复现原症状 |
| 编译通过 | 当场 tsc --noEmit / ruff 零错误输出 | 引用上一条消息的编译结果 |
| 是 XX 根因 | 跑命令/读官方文档复现并定位 | 凭内部记忆直接断言、打算事后补证 |
| 远程/配置是 XX 状态 | 当场查远程/读配置文件的真实回显 | 凭印象判定"不存在 / 已设置" |

与 deploy-acceptance-independent-verification.md 同源协同：那条管"部署验收用宿主真实状态、独立核查三件套"，本条把"下结论前当场跑新鲜命令、不复用旧输出"抽成通用五步闸，覆盖所有完成出口。
