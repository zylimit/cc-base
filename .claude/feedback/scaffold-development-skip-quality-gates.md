# 脚手架开发遵循用户明确的质量门禁豁免

**问题描述**：框架默认流程包含代码审查、测试完整性、回归用例和完成前验证门禁。用户明确修正：开发脚手架内核这一轮，不用测试、不用检视、不写用例；并进一步限定这只是本轮维护 cc-base 内核的执行豁免，最终交付的脚手架仍应保留审查、测试和用例能力。主 Agent 此时是脚手架开发者，不是使用脚手架开发业务产品，不能让被开发对象的运行规矩反过来绑死本轮维护工作。

**触发场景**：维护或开发 cc-base 这类 Claude Code 脚手架时，用户明确要求本轮跳过测试、代码检视和测试用例，或明确说明脚手架开发者暂不受脚手架自身业务开发流程约束。

**教训/建议**：明确区分「开发脚手架内核」和「用脚手架开发业务项目」。前者按用户对本轮维护的明确约束执行，可跳过默认 code-reviewer/tester 派发、用例新增与质量门禁；后者仍保留脚手架设计中的完整审查、测试和验收能力。临时豁免只影响本轮执行方式，不得据此删除 tester、code-reviewer、test-builder Skill、用例模板或最终脚手架的质量保障规则，也不外推成未来任务的永久约束。
