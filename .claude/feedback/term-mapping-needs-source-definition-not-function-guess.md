# 术语对照表的每一行要有原文定性，不能靠功能位置推等号

**问题描述**：2026-09-11 整合 ODN 资料时建「传统 vs 预连接」器件对照表，主 Agent 把「接头盒 / Closure」与「X BOX」写成了同一行的两种叫法。依据是自己的推理——两者都在馈线段做分纤，功能位置相同。用户直接点破：「接头盒/Closure = X BOX 这个理解不对」。回去翻原文，定性句白纸黑字摆在那儿：「预制配线箱，**类似 ODF**，英文名 XBOX；预制光交箱，类似光交箱 FDT 或一分箱，英文名 HUB BOX；预制分纤箱，类似分纤箱 FAT 或二分箱」——三组对应关系原文一次性给全了，而主 Agent 建表时没去找这句话。更糟的是改了一版还没改对：改成「对应 ODF 这一层」之后，用户再纠一次「XBOX 只有预连接场景才要」——原文那句「类似 ODF」是形态类比，不是说传统场景存在对应器件。

**触发场景**：把两套命名体系对起来的时候。多源资料里同一个东西叫法不同，对照表是整合的核心产物，而「功能位置相同」是个特别顺手也特别容易错的依据——位置相近的器件往往恰恰是两个不同的东西（接头盒管接续分歧保护，XBOX 管配线转换，两者在预连接体系里并列存在）。

**教训/建议**：
- **对照表的每一行都要能指到原文的一句定性**。资料里通常真的写了「X 类似 Y」「X 又叫 Y」这种句子，找它比自己推快也比自己推准。找不到就别写成断言。
- **「功能位置相同」不是等号的依据**。同一段落里并列存在的器件，功能位置天然相近，这恰恰是最需要区分的地方，不是可以合并的理由。一个反证信号：如果两者在同一份产品清单里是**并列的独立条目**（本次「多芯接续盒 / 单芯接续盒 / 分支盒」与「X box」就是各占一条），那它们一定不是同一个东西。
- **类比句要读准是哪一层类比**。「类似 ODF」说的是形态（都是配线箱），不等于「传统场景里有个对应物」。把形态类比读成场景对应，就会凭空造出一个不存在的对应关系。
- **被纠错后不要只改被点到的那一处**。同一套错误推法通常产生了好几行，要回头把用同样方法填的其它条目一并重核。本次第一遍只改了被点名的那一行，第二遍才被用户纠出措辞仍不对。
- 与[[skill-invocation-persuasion-gate]]里那句「我知道这意思」同源：对熟悉的领域概念最容易跳过查证，而对照表恰恰是错了最难被发现的产物——它读起来像一份已经核过的结论。

**适用范围与例外**：适用于任何两套命名体系的对照表。原文确实没给定性句、只能靠功能推断时，标明「推断」并留待确认，不要混进断言里（本次文档第 20 节就留了这类待确认项）。

**本次落地**：`docs/domain/odn-design-principles.md` §2 对照表改了三处——「光缆接续 / 分歧 / 保护」单独成行对到接续盒与分支盒；XBOX 那行的传统侧改为「无——传统场景不存在这一层」并标「仅预连接场景使用」；表上方补了原文定性句原样引用。**尚未落干净**：同节下方「易错点」段落仍留着第一次修正时的措辞「对应传统体系里 ODF 那一层」，与表格行的「传统场景不存在这一层」自相矛盾，属本条教训最后一款（只改被点到的那处）的残留，待修。
