# 研究下钻按指定递归深度执行，不能用平级数量冒充深度

**问题描述**：在学习参考项目时，主 Agent 已派出一个 fresh Sub-Agent，用户随后明确要求「往下多打 2 层，加强吸收」。这个修正指向的是委派树继续向下递归，而不是在同一层增加更多并行研究者。若只做平级 fan-out，即使读取数量变多，也没有形成逐层分解、回传、质询和验证，不能满足用户要求的研究深度。

**触发场景**：用户在项目学习、规范吸收、架构调研或复杂材料分析中，明确提出「下钻」「向下多打 N 层」「递归研究」「加强吸收」等层级要求，或明确区分深层分解与平级并行时。

**教训/建议**：先把用户要求转换为可验收的委派树深度，并按指定层数真正建立父→子→孙等递归链路；不要把更多同层 Sub-Agent 当成更深研究。注意 cc-base 扁平编排铁律下 Sub-Agent 不自拉 Sub-Agent——递归由主 Agent 分轮驱动：上一层回传后，主 Agent 据其结论收窄边界再派下一层 fresh 实例，层层递进。每一层必须有不同且收窄的研究边界、可追溯的证据路径，以及对下层回传中共识、分歧和不确定项的整理；上层要交叉验证下层证据后再继续汇总，主 Agent 最终仍须亲读关键材料并保留采纳判断。验收时同时核对「实际递归层数」和「每层新增了什么分析价值」，不能只统计 Agent 数量或读取文件数。
