# 工程师看的可视化：红绿线自己说话，不配字不放大字

**问题描述**：为「端到端问题可视化」，主 Agent 主动提议墙顶放大字「156 路只通了 66 路」，点红线后亮点沿链走并配白话解释断点。用户两次纠正，原话：「不用说明什么打字，没用，一堆红线就吓死了，什么勘测质量」「用大字，反而不适合，大家都是高材生，懂」。

**触发场景**：用户先前说过受众"水平差"，主 Agent 把它理解成"看不懂字"，于是主动加了说明文字和口号式统计。实际上受众是受过高等教育的工程师，看红绿线就懂；多出来的字既没用，大字统计和一堆红线叠在一起还有吓人、像在评价人的副作用。

**教训/建议**：
1. 面向现场工程师的可视化，信息只由图形本身（红绿线、亮点、位置）承载；不默认加解释文字、大字统计、标语。
2. 用户说受众"水平差/不懂"时先问清差在哪（不懂业务？不会操作？），不自行等同于"看不懂字"再去补说明。
3. 设计提议里"加说明让人看懂"是主 Agent 自己的设想，不是用户要求；先给最简版本，不预先堆叠。
4. 与既有条目同向：展示页只放实际数据（presentation-only-actual-data-no-inference.md）、界面标签不生造术语（domain-ui-labels-no-invented-jargon.md）。

**适用范围与例外**：现场工程师 / 领域专家看的图、墙、地图。给外部非技术读者的材料不在此列（未验证，需另问）。图例等读图最小标注是否保留，用户未表态。
