# 改家底/写规则文档时的风格一致性铁律

**问题描述**：
commander 在改造 ccb-base 自己的家底（往 product-spec-builder、dev-planner、CLAUDE.md 等 skill/规则文档里新增内容）时，写出的新增段落带明显「AI 味」，被用户揪出。用户连续两次强调风格问题，第二遍情绪更强：
- 第一次："尽量保障写进去的风格和之前的类似"
- 第二次（更强烈）："你加东西一定要和我之前风格一样哈，和我家底的风格一样，看上去像我手搓出来的，不是你生成的""你都去扫一遍，改一改说法"

核心诉求：改/加家底（skill / 规则 / 文档）时，新增内容必须**无缝贴合原有家底风格**，让人看不出哪句是 AI 后加的、哪句是用户手搓的——规则文档要浑然一体。家底几乎全中文、短句、直白毒舌、给铁律不解释，AI 默认的工整学术腔与之格格不入。

**AI 当时犯的「AI 味」错误（被用户揪出）**：
1. **英文缩写堆砌**：SMART / BDD / Non-Goals / Acceptance Criteria / Edge Cases 这种括号英文术语——家底几乎全中文，极少用洋缩写。
2. **元叙事 / 下游机制罗列**：写「这东西会驱动 dev-planner 的 Task 验证 + dev-builder 的 TDD 红测 + trace-matrix 追溯」「是一条链的源头」「AI 不能从省略推断意图」这种解释来龙去脉、罗列下游怎么用的长句——家底是直接给铁律，不解释。
3. **花哨标记**：⭐、← 箭头、「链路源头 / 链路核心」这种自我标榜强调——家底朴素，占位符用 `<尖括号>` / `[方括号]`，不加 emoji。
4. **过度工整对称、爱解释「为什么」**。

**触发场景**：
任何「改家底 / 写规则文档 / 往 skill 或 CLAUDE.md/AGENTS.md 新增内容 / 写新 feedback」的动作。尤其当 AI 默认调动学术写作惯性（分点工整、术语包装、补 why 解释）时最容易跑偏成 AI 味。

**How to apply（怎么做）**：
1. **贴合家底语态**：短句、直白、毒舌口语（"废纸""惯着""糊弄""没想清楚=继续逼问""不是写着好看的""万金油"），给铁律不解释来龙去脉。
2. **占位符 / 章节名风格统一**：占位符用 `<...>` / `[...]`，章节名纯中文，不堆英文缩写，不加 ⭐/← 这类装饰标记。
3. **改前先 grep 核查家底本来用不用某词——别凭空认定是 AI 味矫枉过正**（关键，本次踩过的反面坑）：本次差点把"锚定 / 契约 / 驱动 / 闭环"当 AI 味要改，一 grep 发现家底原文大量在用（"胜负锚定能否复现""定义契约""驱动适配层""review→fix 闭环"），于是没动。判断"是不是 AI 味"必须对照家底实际用词，不能凭空拍。
4. **保留有机制意义的功能性标识**：编号 AC-xxx、格式 Given-When-Then、工具名 trace-matrix——这些有机制意义、不是装饰，不在"去 AI 味"清扫范围。
5. **写完自扫一遍**："这段读着像用户手搓的还是像我生成的？"——有学术腔/英文缩写堆砌/元叙事罗列/花哨标记就改说法。

**关联**：
- 与 preserve-existing-framework-assets-human-approval-to-remove-hook **正交互补**：那条管「别删家底」（存量受保护、删须人工审批），本条管「加/改家底时新增内容要贴合家底风格」——一个保命、一个保形。
- 与 record-config-files-concise-conclusions-not-process 同属「写入家底文件的质量约束」家族，但角度不同：那条管 progress/配置文件「记结论别记过程」（简洁性），本条管 skill/规则文档「新增内容风格要像手搓」（一致性）。

**evolution-engine 信号**：
CLAUDE.md / skill-builder / 各 skill 目前没有「改家底/写规则文档时新增内容必须贴合家底风格、去 AI 味」的显式约束。建议进化时：① 在 skill-builder skill 或 CLAUDE.md 增「家底编辑铁律：往 skill/规则/CLAUDE.md/AGENTS.md/feedback 新增内容时，风格须无缝贴合存量——中文短句直白毒舌、给铁律不解释、占位符 `<>`/`[]`、不堆英文缩写、不加 ⭐/← 花哨标记；改前先 grep 核查家底是否本就用某词，别凭空当 AI 味；保留 AC 编号/Given-When-Then/工具名等功能性标识」；② 给"判断是不是 AI 味"加 grep 自检步（对照家底实际用词，不凭空认定）；③ 可考虑做轻量 AI 味自检清单/钩子（扫新增段落里的英文缩写堆砌、emoji 装饰标记、元叙事长句），但务必保留功能性标识白名单防误杀。
