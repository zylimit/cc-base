# 多源资料整合按主题去重，不按来源堆砌

**问题描述**：2026-09-11 收 19 份 ODN 资料（PDF/PPT/PPTX/DOCX，合计约 250 页），内容大量重叠——缆长选配表出现 4 次、器件插损表 3 次、FAT 链的定义 5 次，同一件事在不同资料里还各用各的叫法。主 Agent 第一版有按资料来源并列组织的倾向（这份讲了什么、那份补了什么）。用户一句话纠正：「你要统一收拢，去重」。改法是推倒重组：按主题收拢成 20 节，同一判据只落一处，重复的表合并，术语别名统一成一张对照表。

**触发场景**：把多份来源整合成一份基线时。来源越多重叠越大，而「每份都有贡献」这个念头会诱导出按来源并列的结构——读起来像做了整合，实际是把去重的工作留给了读者。

**教训/建议**：
- **产物形态是一份去重的知识，不是 N 份摘要的拼接**。组织维度取自主题本身，不取自资料的来源和篇目顺序。
- **同一判据只落一处**。别处需要就引用那一处，不重述。一个数字在文里出现两遍，将来就会有一遍改不到。
- **重复的表合并成一张，把来源间的差异做成列**（如缆长表合并后用「架空/管道」「支持接续/不支持」作列，而不是四张表并排）。
- **别名先统一成一张对照表**。多源资料最大的重复来源不是内容，是同一个东西的不同叫法；对照表建好，正文就不必每处都解释一遍。
- **冲突值并列标注，不擅自取舍**。整合时最容易犯的是「挑一个看起来权威的写上去」——那是把判断偷偷替用户做了。本次 7 处数值冲突（单 OLT 用户数 ≤5000 vs 2000~3000、端口渗透率 60–100% vs 80–100% 等）全部并列并集中列出，标明「两种口径」。
- 判断产物合不合格的一条实操检验：**随便挑一个数字，看它在文里出现几次**。超过一次，就是没收拢干净。

**适用范围与例外**：适用于多来源整合成基线/手册/口径库。用户明确要「逐份摘要」或「按来源归档」时按用户的来；产物主题本身就是版本/来源对比时，按来源组织才是对的。
