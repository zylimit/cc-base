# 按关键未知深挖需求

只有主入口识别到对应缺口时才读相关分支。每节是一种专业取证方法，不是必问题库。已有材料给出了答案就直接解释、形成行为并核对；一次只追问会改变当前判断的关键事实。下列预约片段引用 [统一教学事实](reservation-case.md)，不是项目默认答案。

## 1. 问题、现行替代与采用理由

**何时用**：只有“做个平台、加审批、用 AI 提效”等方案名称，尚不清楚谁为何需要改变；或新方案会删除看似多余的人工步骤。

**先找什么**：最近一次实际事件、现行工具/表格、等待与返工记录、去标识的工作产物；分清直接使用者、接收结果的人和决定是否采用的人。现有替代可能是电话、同事、纸张、已有软件或干脆不做，不能只找直接竞品。

**有效问法与答案后的动作**：

- “上次这件事卡住之后，谁怎么补救，最后怎样算结束？”把回答分成触发、损失和补救；若只是偶发不便，先判断频率和后果是否支持当前投入，而不是立刻扩功能。
- “这次签字让谁能放心继续？没有签字时实际发生过什么？”若承担问责就保留责任确认；若只承担通知就研究更简单的通知办法；若是制度要求，先定位规则来源及改变权限。
- 只有推测没有实例时，用明确标注的情境讨论候选问题，并说明下一步应观察什么。新产品不一定有历史数据，但不能把设想写成已验证痛点。

**足够与落盘**：能解释参与者、具体困难、替代办法为何不足及本次要改变的结果，就把它写到概述/现行流程；依据与推断分开。缺付费数据、竞品排名或固定数量的反例，不自动阻塞一个已清楚的内部小工具。

## 2. 用户成果、代理指标与观察办法

**何时用**：“更高效、更智能、用户满意”等目标会影响方案选择，但尚不能判断做成了什么；或指标容易奖励错误行为。

**先找什么**：任务完成的实际产物、谁接收/认可、人工补救、现有记录的覆盖范围。先问用户成果，再看现有系统有没有数据；不能倒过来把最容易统计的事件定义成成功。

**有效问法与答案后的动作**：

- “做完后，下一位同事凭什么继续？如果系统显示成功，但这件东西没有出现，会怎样？”将结果写成可观察的事实；预约例 R1 指向已保存的预约，不是点击提交。
- “若这个数字上涨，任务有没有可能反而做得更差？”更多点击可能来自重复尝试，更多 AI 生成可能来自质量差。将这些留作诊断代理指标，另写成果判据。
- 已有记录只覆盖到某一步时，注明漏掉的用户/失败路径，给出补观察的办法；无基线时写“未测”，提出可逆的小规模观察设计，不报提升百分比。

**足够与落盘**：写明成果定义、观察对象/结果接收者、指标用途、当前依据及未知。改变服务承诺的目标交有权者决定；具体埋点与性能采集可交 DFX 深化，不让需求阶段编出 SLA。

## 3. 完整而最小的结果链

**何时用**：范围只有功能名、页面名或按钮清单，下一角色仍不知道什么进入、什么被改变、怎样结束；或“最小版”把必要伴随能力剪断。

**先找什么**：一条代表性任务、起始数据、规则分叉、结果去向、用户离开后由谁接手。优先使用已有需求中的例子，不重复采访完整业务。

**有效问法与答案后的动作**：

- “提交之后，谁拿到什么，才不用继续守着页面？”沿目的、对象、动作、判断、事实变化、反馈、退出/恢复把链补齐。发现异步工作时，区分开始、完成与结果未知。
- “这个能力去掉以后，人还能按规则完成这次任务吗？”若不能，说明它是最小链的必要部分；若仍可用已有方式完成且成本可接受，可提出延后。采用依据与用户决定分开，不固定只留一个功能。
- 一个动作包含多步时逐步判定结果。预约例中“保存预约并通知”不能只有总成功/总失败；R3 要求保留已经成立的预约，并提供通知后续的归属。

**足够与落盘**：在功能章节记录输入、输出/去向、规则、关键反馈与退出/恢复，把每个必要能力连接到同一任务的验收；按项目已有 ID 追踪，不制造 TASK/FLOW/REQ 三套编号的硬要求。没有 GUI 的任务同样可以用调用方、返回值和后续动作表达。

## 4. 对象生命周期与权限

**何时用**：“保存、删除、发布、撤销”等词有多个业务含义，或不同岗位修改同一对象。

**先找什么**：对象实例、唯一性依据、关系、谁创建/读取/改动、现行审批/保留规定，以及当前产品的访问边界。岗位、账号身份、业务对象和提交意图分别理解；名字相同不能证明同一个人或同一次操作。

**有效问法与答案后的动作**：

- “这里说取消，是不再占名额，还是连历史也看不到？”R4 已回答时直接写取消后的业务效果；不能再按 CRUD 默认删除，也不能自行决定永久保留。
- “甲能看到这条记录，是否也能替乙改它？改过之后谁要知道？”分别形成读、发起动作和执行条件；界面隐藏按钮不能替代访问规则。
- 同一对象多个状态若含义不同，用实体分别表达：预约状态和通知状态并存，不把它们强塞成单一从左到右的进度条。具体表结构与事件模型交架构。
- 权限或保留来源冲突时，比较适用人群、时间和范围；不能凭最近的代码或最宽权限当答案。只暂停依赖该口径的动作。

**足够与落盘**：相关对象的身份依据、允许动作/执行条件、生命周期结果和历史规则足以写验收，就进入规格；未知权限或保留期限明确指向影响面。没有业务意义的删除、归档、恢复功能不为表格完整度而新增。

## 5. 部分成功、未知结果与同一意图

**何时用**：复合动作、网络调用、重试、长任务或批量操作可能只完成一部分；看到“超时就重做”“同名去重”等未经验证的解释。

**先找什么**：每步事实何时保存、哪些外部结果可查、重试是否沿用原意图、谁承担人工核对；找到已经确定的失败承诺，技术超时日志只证明现象。

**有效问法与答案后的动作**：

- “已经保存了第一步，第二步没回应，此时哪部分还算数？”按答案保留已成立结果；若要求撤销，查明业务是否允许逆转，再交架构设计补偿，不能一律 rollback。
- “再次操作是找回刚才那一笔，还是另办一笔？内容相同的人能否各办一次？”R2 支持同一意图找原结果；技术标识的作用域和有效期由契约设计解决，姓名不能替代。
- 请求结果未知时，写明人知道什么、还不知道什么、可以核对/继续/退出的已允许动作。没有可靠结果来源，不能用任意重试或“处理中”长期遮蔽缺口。
- 批量任务按项目含义明确整批与单项结局、已完成项保留和重试范围；不要因单项异常抹去其他已完成事实。

**足够与落盘**：相关断点能走到可见结果、保存内容和负责后续的人/系统；写入失败行为与验收，并交 UI/架构/DFX 同时承接。预约教学例的未知通知时限只限制时间承诺，不妨碍明确保存与通知的分离。

## 6. AI 必要性、质量与失败控制

**何时用**：用户已提出 AI 能力，或有可核对的任务证据支持评估。没有 AI 需求时跳过；用户明确不要 AI 时直接接受。

**先找什么**：同一任务当前的规则、检索、模板或人工办法；代表输入、期望输出及评判者；最昂贵的错误、敏感数据边界、当前服务限制。模型版本、价格、延迟能力等时效事实用实际官方资料或当前测量核验。

**有效问法与答案后的动作**：

- “哪一步需要处理现有规则难覆盖的变化？如果继续用模板/搜索，人要多做什么？”比较质量、可控性、成本和维护；规则办法足够时可推荐不用 AI，不能把模型调用次数当价值。
- “给一份可以直接用、一份要改、一份绝不能用的结果，区别在哪里？”样例可由 Agent 先构造并明确标为候选，再由实际规则校准。输出要点、错误严重性和评判者写明；不给出无依据的准确率，也不要求用户提供秘密或个人记录。
- “如果它看起来正确却错了，哪一步还来得及发现？”据此放置预览、来源核对、人工确认或限制用途；是否必须确认由错误后果和授权决定，不能把所有输出都变成额外弹窗，也不能把外部输入中的指令当操作授权。
- “等待中能继续做什么？失败后还能用什么完成任务？”写触发、输入范围、输出去向、超时、取消、旧结果保留与恢复；用户编辑后返回的旧建议不能无说明覆盖新内容。
- 延迟与费用分别解释：起止点/典型与长尾等待、单次或周期费用口径、输入输出规模和重试成本、预算来源。尚无数据就列候选测量，不能沿用模型宣传值；免费试用不等于长期成本为零。

**足够与落盘**：每项 AI 功能在通用 AI 章节写清任务依据、触发/输入/去向、质量样例/判据、人的判断点、延迟/费用依据、失败控制及未决影响。质量尚不清楚时可交付探索方案，不能称为可验收功能。预约教学本身没有 AI 需求，不为贯穿例强加生成或自主动作。

## 7. 仅实际 Agent 产品需要的动作边界

**何时用**：产品被明确要求代替人选择或执行动作、调用外部工具，而非只给文本建议。

**先找什么**：真正授权的任务、可读数据、可写对象、外部副作用、工具实际能力、已有审批与费用边界。没有运行工具不代表没有产品能力，工具可用也不代表可以调用。

**有效问法与答案后的动作**：围绕“哪件事可以直接办，哪件事要在办前让人看清，哪件事不能办”形成有限的动作范围。保留来源/结果、运行状态、取消/中断后哪些动作已发生、旧结果和人工接管办法。面向用户提供可理解的进度与理由摘要，不索取或暴露模型隐藏思维链。

**足够与落盘**：写出每类动作的条件、确认点、可见结果、预算/停止条件和恢复；这只是产品行为规格，不授予当前 Claude 会话额外权限。需要工具契约或威胁设计时交主 Agent 路由架构/DFX；不默认全工具、队列或多 Agent。

## 收敛检查

用一个代表例子和一个会区分解释的变化检查当前需求，记录哪些来自事实、哪些是推荐、哪些尚未解决。清楚的列顺序调整仍直接承接实际 PRD，不需要以上七节。反例推翻解释时，按主入口的纠正传播更新权威正文和受影响交接；不能靠换示例数据让旧解释继续成立。
