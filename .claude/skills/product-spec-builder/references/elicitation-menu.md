---
name: elicitation-menu
description: 风险档位为对外或涉钱涉合规的 Spec 在复述前读。深挖方法菜单：摆 3-5 种最相关的给用户点，点了才跑，最多两种；每种给出它揭示了什么、提议改什么，用户接受才改 Spec。
---

[定位]
    这是可选的压力测试，不是流程的一环。用户不点不跑；跑完给「揭示 → 提议」，用户说接受才写进 Spec，拒绝就丢掉整条提议。每次只对当前 Spec 的最近一段或一条决策用，不整篇重跑。

[怎么摆菜单]
    按 Spec 的风险选 3-5 种，一行一种（名字 + 一句它能抓住什么），加「都不用，继续」。用户可选一种或几种。
    跑一种：按它的思路把发现列出来，最多五条，每条指到 Spec 的段落；然后提议改动；停下等用户接受、拒绝或给别的方向。

[方法]
    | 方法 | 一句话 | 什么时候最值 | 输出形状 |
    |---|---|---|---|
    | 事前验尸（Pre-mortem） | 假设上线六个月后失败了，倒推「要是当初……就好了」 | 对外产品、核心流程重做 | 失败情景 → 原因 → 现在能堵的 |
    | 反向思考（Inversion） | 问「怎样保证它一定失败」，把答案反过来 | 范围膨胀、目标空泛 | 目标 → 反转 → 失败路径 → 避开 |
    | 假设审计（Assumption Audit） | 把 Spec 里每条 `[推断]` `[默认]` 列出来，按信心 × 影响打分，压力测试最弱的 | 推断多、待定多 | 清单 → 打分 → 最弱三条怎么验 |
    | 干系人轮换（Stakeholder Lens Rotation） | 依次站在受益者、买单者、变差者、运维者的角度重读 Spec | 受益者与买单者不是同一人 | 视角 A / B / C → 被忽略的需求 |
    | 钢人论证（Steelmanning） | 把用户否掉的方案写成最强版本再比较 | 用户坚持而 AI 有异议 | 对方观点 → 最强形式 → 诚实比较 |
    | 事后之明（Hindsight 20/20） | 想象产品已经成功，回头看哪一步最关键、哪一步差点毁掉 | 成功判据不清 | 未来视角 → 关键一步 → 现在补什么 |
    | 五个为什么（5 Whys） | 对现状痛点连问五次为什么，找根因 | 现状故事只讲了表层症状 | 为什么链 → 根因 → 该解决的是不是它 |
    | 重构问题（Reframe the Question） | 质疑「用户说的问题是不是真问题」 | 用户上来就给方案 | 陈述问题 → 重构 → 真问题 |
    | 边界扫描（Boundary & Edge Case Sweep） | 系统地过零值、空、极大、并发、类型不符、断网 | 涉钱、涉数据、涉外部接口 | 输入 → 边界 → 失败点 |
    | 级联失败（Cascading Failure Simulation） | 一处失败沿依赖传播到哪，暴露隐藏耦合 | 依赖外部系统、多角色流程 | 触发 → 传播 → 放大点 → 解耦 |

[纪律]
    - 每种方法的发现要指到 Spec 具体段落，不泛泛。
    - 发现不等于需求：写进 Spec 之前必须用户接受，接受的标 `[确认]`（来源：深挖 + 用户确认），只是提醒的进待定表或「以后」清单。
    - 跑完两种就停，除非用户再点。
