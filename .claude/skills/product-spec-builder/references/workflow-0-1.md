name: workflow-0-1
description: product-spec-builder 0-1 模式启动时读。从用户初次表达到生成 Product-Spec.md 的顺序、每步的出口判据与完成度判据。
---

[使用时机]
    项目里没有 Product-Spec.md，用户第一次表达想做产品。

[顶层规则]
    先听用户开放描述，从里面抽取已表达的维度复述确认，不让他重复回答已说过的。
    地基（question-bank 1-4）过了才解锁细节；5-11 按产品裁剪；12-13 只在产品用 AI 或本身是 Agent 时展开。
    形容词永远不算合格答案，逼出具体见 interview-principles 的四把刀；每个阶段结束默扫反失败自检。
    采访期间不写文档，用户答完只更新自己的理解；收敛后一次性生成，再复述。
    分级采集：地基字段（现状、受益、规则例外、谁说了算、成功判据、范围、关键流程、数据）问到底；产品形状与细节（布局、文案、技术偏好）能推就推、推不出进待定表交设计和开发，不为它们拖着不生成。

[第 0 步 · 进场]
    WebSearch 用户提到的领域与竞品，带具体例子进场。问一句风险档位：自用 / 内部 / 对外或涉钱涉合规——它定问题预算与 Spec 长度。
    用户只给一句短想法时，第一问固定：「先别列功能。按真实使用过程讲一遍：谁会用它，他当时在做什么，最卡在哪里，最后希望手里得到什么？」
    用户已经给长描述、旧文档、截图时：先读材料，抽取已覆盖的维度，用一段话回放，只问没覆盖且会改变方案的。

[第 1 步 · 地基：向人学业务]
    按 SKILL.md [向人学业务] 四条线，一次一条，每条问到能用一个具体案例复述。
    出口判据：能复述「谁、什么问题、今天怎么凑合、这事值多少、谁受益谁买单、规则与例外、谁说了算」，用户点头。
    衔接话术：「基本盘清楚了：这是给 [谁] 在 [情境] 解决 [问题] 的，现在靠 [现状]，卡在 [哪步]。接下来把上线后那次怎么走过一遍。」

[第 2 步 · 覆盖扫描与细节]
    按 SKILL.md [覆盖扫描] 十类标清楚 / 部分 / 缺失，只对缺了会改变要做什么的起问，按影响 × 不确定排序，一次一问，每问带推荐。
    这一步覆盖 question-bank 5-11：成功判据、范围与非目标、关键流程与失败路径、数据与权限、产品形状、非功能与隐含合规、术语与矛盾。
    产品要用 AI → 展开 12；产品本身是 Agent → 展开 13。
    用户提到上传 / 画布 / 生成 / 长任务 / 外部接口 / 删除 → 翻连带需求触发器，只提最相关的 1-2 项。
    到预算先做收敛审计：剩余未知真会改变首版吗、能不能用默认、该不该进待定表、是不是设计阶段的问题。

[第 3 步 · 收尾三件套]
    覆盖清单逐类过一遍；元问题「我该问而没问的是什么、还该找谁」；把结构化摘要读回让用户纠正。
    风险档位对外或涉钱涉合规的，把 elicitation-menu 里最相关的 3-5 种摆给用户点，最多跑两种。

[第 4 步 · 需求单元测试]
    生成前对照 spec-self-review.md 逐条过：测的是需求写得好不好，不是系统。过不了的回第 2 步补问或改写。

[第 5 步 · 生成与复述]
    生成前再 WebSearch 一遍：按已聊出的核心功能、技术方向搜当前做法与可行性，让技术方向是当前的、有针对性的。
    按 templates/product-spec-template.md 生成，跑 spec-lint 与 predev-lint。
    然后按 SKILL.md [复述理解] 用用户的案例讲一遍上线后那次会怎么发生，用户挑不出错即通过。

[完成度判据]
    什么叫够了，三个判据一起看：
    - 交接测试：把 Spec 交给一个没参与对话的工程师，他能直接开工不用猜吗？需要猜的地方就是还没够。
    - 边际测试：再问一个问题，答案会改变要做什么吗？不会，就别问了。
    - 不对称原则：缺了会让开发返工的（地基、范围、关键流程、规则例外、数据归属）必须问到底；缺了以后便宜能补的（边角样式、二期功能）进待定表直接放行。
    阶段级：能用自己的话复述该阶段的内容，用户点头，就进下一个，说一句「这块我够了」。
    整体级：关键需求约 80% 置信，剩余都是便宜能补的，就停。完美是敌人，可执行是目标。

[生成后]
    告诉用户读一遍看哪里要改；列出 `[推断]` 与 `[待定]` 各几条；引导下一步：/design-brief-builder（有界面）、/arch-designer（多模块）、/dfx-designer（涉钱涉人身涉合规）、/dev-planner。
