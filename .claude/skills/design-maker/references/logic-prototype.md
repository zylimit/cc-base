# 业务逻辑沙盘：用可操作状态回答一个问题

> codex-base `407c3bc` 教学材料；预约例是虚构案例，其中数字、命令、路径不自动成为本项目要求。

当用户想让领域人员亲手检验一条状态、规则或事件顺序，而暂时不需要完整 UI 设计稿时读取。交付物是能双击离线打开的单个 HTML，默认放 `demo/` 下单独命名的文件（如 `demo/logic-<问题简名>.html`），不覆盖全稿 `demo/index.html`；已有同类沙盘沿用实际路径。不能把文字转移表当成已交付沙盘。

## 先限定问题与事实

用一句业务语言写出「操作者改变什么、观察什么、哪两种结果会改变设计判断」。列出实际来源、已知初态、已确认规则、尚未知晓的业务取舍与它阻断的决定。未知允许保留为候选分支，不能编成确定规则；不影响问题的未知不阻断制作。只纳入回答这个问题所需的对象、状态和事件，不要求先冻结品牌或全套视觉方向。

给参与者一个目的与简短引导场景，不把点击顺序写成唯一答案。说明哪些初态和结果是虚构模拟，哪些规则来自已确认来源；观察者记录实际选择、可见结果和疑问。一个样例运行不能证明业务人员认可。

## 做成能自由操作的单文件

1. 页面可见地写出问题、来源/模拟边界、已知初态和引导场景。用业务名称显示每个相关对象的状态、事实来源或未核实标记、最后触发的事件；相关的两项事实分别显示，避免一个「成功/失败」吞掉另一项结果。
2. 把已确认的转移写为独立的内存状态更新函数；把 DOM 渲染与事件监听分开。事件按钮调用状态更新后统一重绘。需要用户编辑输入时，使用有标签的原生控件；事件参数和请求/对象身份明确。默认不持久化，刷新丢失；不连接数据库、通知服务或真实外部变更，除非问题和授权确实涉及它们。
3. 提供正常、异常、结果未知和不允许动作的可触发路径。对不允许动作给出原因和可用下一步；已发生的业务事实不因通知失败、关闭反馈或旧回应而被假装撤销。未知结果只能由有依据的模拟查证事件转为某个可见结果，不能自动显示成功。
4. 设置独立的「重置演示」控件，恢复所有模拟对象、输入、请求代次、反馈与事件记录到声明的初态。重置属于演示控制，不冒充业务取消、回滚或后端清理；按已确认规则提供真正的取消等业务事件时，另用业务名称并保留历史。
5. 用可见的事件记录或状态变化说明「发生了什么、保存了什么、仍不知道什么、下一步能做什么」。允许操作者按任意顺序触发适用事件并重复同一意图，不把引导场景硬编码为唯一可行按钮序列。若顺序会影响结果，用显式排队/交付按钮控制到达次序，旧反馈不能无说明覆盖当前编辑内容；旧请求对应的业务事实仍应可追踪。

推荐的最小组织是 `initialState()`、`transition(state, event)`、`render(state)` 和事件绑定；这是职责示意，不要求框架、固定数据 schema 或额外层。先用一个完整事件链检查状态归属，再实现相关异常；无需为了沙盘做整套产品 UI、导航和视觉 token 系统。样式只需保证阅读层次、焦点可见与窄屏可用。

## 预约教学例的可判定操作

使用此例先读 `../../product-spec-builder/references/reservation-case.md`。可设一个演示时段、一个提交意图和一条通知事项。操作者能重复同一意图，看到同一预约结果（R2）；触发回应丢失后看到「结果未知」，再按同一意图模拟查证，不能把未知当失败（R1）；触发「预约已保存、通知失败」，应分别看到预约成立和待处理通知，通知失败不释放预约（R1/R3）。若演示取消，应释放演示名额且保留已取消历史（R4）。通知送达口径、编辑后意图身份、取消权限等仍在来源中未知；用说明或候选分支展示影响，不擅自定规则。

如需检验迟到回应，补可控的 Q1(草稿 v1) → 编辑 v2 → Q2(v2) → 先交付 Q2 → 再交付 Q1；当前草稿反馈保持 v2，Q1 来源与结果仍可查。不要从客户端反馈推断服务端是否创建了一笔还是两笔预约，除非真实契约已确认。原型发现跨事实归属的冲突时，交主 Agent 同步需求、架构、DFX 与 Task。

## 核对与交接

实际打开文件，按引导路径和一个自由顺序路径操作：重复、异常、未知、被拒动作与重置后重演；核对事件前后状态与规则来源，记录保留或推翻的假设。按 SKILL.md [第一性原则] 的离线自包含与质量地板核对离线资源、键盘路径、焦点、状态播报、窄屏和实际渲染。浏览器不可用时，静态检查状态面板、事件按钮、重置、异常路径、脚本语法及资源引用；明确浏览器交互、键盘和视觉均未执行，不能写成已通过。

交接时给出 HTML 路径与打开方式、问题和来源、可试走事件、实际观察、模拟/真实边界、未决规则，以及需要回填的业务来源和 Task。若要把实验代码带入产品，按生产数据契约、权限、并发、恢复与验证要求重新实现和校验；一次沙盘试走不是生产证据。
