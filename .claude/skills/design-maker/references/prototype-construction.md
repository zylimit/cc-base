# 从关键屏制作、查看和修正原型

> codex-base `d1a3287` 教学材料；预约例是虚构案例，其中数字、命令、路径不自动成为本项目要求。

需要布局实现、组件/状态、直接操作或实际预览时读取相应部分。仍交付仓库内离线自包含 HTML；不要求某种设计工具，不安装新依赖。简单已明确的文案/位置修改只检查受影响部分。

## 1. 选能改变设计判断的关键屏

先承接实际需求和 Brief，定位当前主任务、代表内容、界面形态与最重要的未知。它可能是首次入口、密集比较、结果未知、复杂编辑或错误恢复；不固定一定先做首页。

把任务的对象、状态、必要说明、动作放进实际尺寸的关键屏，先解决阅读顺序、分组、对齐、密度和空间关系。使用安全的真实内容；缺样本时明确虚构，但保留相关长标题、数字、单位和异常文本。不能用几个整齐短词证明真实页面装得下。

如果方向仍有实质性分歧，围绕同一个设计问题提供同内容的小样；已有委托时给推荐并采用，不把每个像素变成确认题。未知业务含义只把依赖区域标成讨论中，其他部分继续。

## 2. 从关键屏沉淀 token，再形成组件

已有品牌值与组件语义优先沿用。新建时，从关键屏已经需要的区别提炼 token，而不是先生成庞大主题库：

- 文本与表面：正文、辅助说明、边界和浮层各承担什么阅读职责；背景变化后仍需核对对比。
- 排版与空间：正文/标题/数字的关系，组内/组间节奏，窄屏与长内容如何延展；保持单位与对应数值相连。
- 颜色角色：主动作、成功/错误/未知、选中、焦点分别有可理解的含义；不能只凭色值表达业务结果。
- 材料与运动：表面层次、必要的动效与 reduced-motion 替代；没有任务依据就不增加纹理、透明层或持续动画。

将这些值集中为 CSS custom properties，然后建立真正重复的组件。优先语义 HTML：按钮执行动作、链接导航、label 关联输入、表格表达二维关系；不要为统一外观把所有元素换成可点击 div。组件包含内容、布局、语义和行为，不只是一组颜色类名。

组件的一致性取决于职责：同一“预约状态”在列表和详情中含义一致；通知状态是另一种事实，可以视觉相邻，不能合成一个无法解释的颜色标签。主题/模式不是默认必需能力。

## 3. 用动作契约展开状态

为会改变结果或容易误解的动作记录下列内容，简单动作可用一段话：

| 项目 | 需要说明什么 |
|---|---|
| 执行边界 | 真实本地交互、模拟后端/外部行为，还是未实现；模拟是否跨刷新保留 |
| 触发 | 对象、输入、前置条件，鼠标/键盘或适用的直接操作方式 |
| 可见反馈 | 用户立即知道什么，哪些事实仍未知；必要状态如何被辅助技术感知 |
| 保留数据 | 输入、选择、滚动位置、已有结果和待完成事项保留在哪里，何时可能丢失 |
| 可用动作 | 当前真正能查询、修改、重试、取消或离开的范围；无权限/禁用说明与规则来源 |
| 退出/恢复 | 怎样结束、返回、修正或重置；有无已经发生而不能撤销的部分 |

真实的本地页签切换可以直接实现；外部通知必须标为模拟。未实现的发送、保存、撤销不靠成功提示掩盖，可以使用清楚的说明或不提供可执行承诺。说明不必塞进每个按钮，原型边界与演示控制应可找到，产品任务区继续用业务语言。

默认、加载、空、错误、结果未知等状态按实际任务选择。必须能从适用触发进入，并能按规则退出或恢复；把八张状态卡摆在旁边不证明原型经历过这些状态。结果未知不能无依据变成功，也不能靠循环转圈掩盖没有结果查询办法。

## 4. 处理异步结果与用户正在编辑的内容

只在存在后台/异步/直接操作时展开。先写时间线：请求发给哪个对象、基于什么输入/版本、当前页面在等待期间发生了什么变化、返回后允许改变什么。

例如原型发出针对对象 A 的建议请求，用户已切换对象 B 或改了 A 的草稿。返回时应根据已确认契约保留旧建议、提示来源/版本或请求重新应用；不能把旧文本直接塞进用户当前正在写的字段。若项目没决定如何处理，做局部讨论样例并交回架构/需求，不能自行宣布“最新回应永远覆盖”。

同理，点“取消”可能只是停止等待、放弃草稿，或请求取消后端动作，含义必须区分。若某一步已经形成业务事实，UI 关闭不应假装事实消失。旧有效结果保留与隐私保留期限也各有来源，不能无限存储。

复杂拖拽、画布、时间线或多选只先验证最重要的不确定性，例如选择对象是否明确、拖拽后结果是否正确、能否用键盘完成等价任务。使用最小可操作片段检验，写观察如何推翻设计；不因“复杂”标签发明新 gate 或预建整套内核。

## 5. 再扩页面与导航

关键屏、组件和核心状态得到实际检查后，将同样规则扩展到覆盖矩阵的其他页面；未能预览时可继续做结构实现，但把视觉与交互结论保留为未验证。新增区域先问它是否承接当前已确认任务，不为展示组件丰富度扩产品范围。

跨页追踪同一对象与当前任务位置，检查返回是否保留必要上下文、错误能否原位修正。窄屏先保证必要内容与操作可用，再决定哪些辅助区域折叠；密集比较若必须横向滚动，应保持关系与可操作性，不能直接隐藏决定所需列。

## 6. 实际渲染、键盘与内容核对

先使用当前可用且获授权的浏览器/预览工具（本仓是 `node .claude/scripts/ui-audit.mjs` + playwright-core，没有引擎时人工用本机浏览器开），以单文件方式实际打开。记录路径/版本、浏览器、视口或缩放、状态与实际动作；截图要确实生成并查看，不能只看文件存在或启动退出码。截图回答画面问题，交互问题还要实际操作。

按当前未知和验收要求执行对应检查，不把下表当新的验证强度规则：

| 检查 | 怎样实际看/操作 | 常见反例 |
|---|---|---|
| 内容层次与视觉 | 看关键屏默认与异常状态；检查主对象、结果、次要说明和动作的阅读顺序 | 失败色覆盖了已成立事实，长标题挤掉主动作，说明比重要内容更抢眼 |
| 长内容、窄屏与缩放 | 换代表长文案/数字，用目标窄屏与适用缩放查看；检查换行、遮挡、滚动和操作可见性 | 为“干净”截断唯一标识、固定底栏盖住错误、隐藏必要比较信息 |
| 完整键盘任务 | 从入口用键盘到结果再退出；看焦点顺序、可见性、操作与返回 | 能 Tab 到按钮却无法激活，焦点跳到页面外，弹层关闭后回到无关位置 |
| 模态焦点 | 开启时进入合适位置，模态范围内导航，关闭后返回合理发起点；检查允许的关闭方式及数据后果 | 只添加 aria-modal 却没有焦点管理；背景仍可操作；非模态卡片却困住焦点 |
| 语义与反馈 | 核对名称/标签/错误关联，必要时以当前可用辅助技术查看状态变化；后台反馈不无故抢焦点 | 图标按钮没有名称，错误只变红，异步状态没有可感知反馈 |
| 动效与输入条件 | 检查 reduced-motion 下的等价结束态；适用时检查触控操作与鼠标悬停以外的路径 | 禁动效后不再显示完成，只有 hover 才出现关键动作 |
| 离线自包含 | 观察实际资源/请求，核对内联 CSS/JS/SVG 与所有核心动作的网络需求 | 内联 CSS 仍 @import 字体，脚本仍 fetch 外部数据，资源URL藏在样式中 |

SVG `xmlns="http://www.w3.org/2000/svg"` 是命名空间声明，不会因此加载网络；纯说明链接也不是运行依赖。检查 URL 的用途：核心动作或显示若依赖网络就不符合离线约定，不能仅搜索协议字符串判定。

使用语义元素、ARIA 或某些符合标准的颜色，不等于完整可访问性通过。占位文字也要考虑可读性，不能和真正不活动的组件一起笼统豁免。标准目标与具体阈值按当前项目适用版本核验，不把所有按钮统一尺寸当某级合规证明。

如果浏览器缺失、无法启动或操作被审批拒绝，明确报告原因和实际未执行项；不要自动安装、改依赖、用未授权的替代路径绕过策略或制作假截图。可以交付源码及可复现的试走说明；静态检查、渲染检查、键盘操作、辅助技术和真实用户观察分别报告。

## 7. 预约例的状态与行为承接

先读 [统一预约事实](../../product-spec-builder/references/reservation-case.md)。原型可提供独立演示控制来触发：

| 教学情境 | 可见结果与保留 | 演示中的后续及边界 |
|---|---|---|
| R1：提交没有收到回应 | 不宣称成立或失败，保留这次输入与意图上下文 | 用模拟查证展示既定分支；“核对”沿用这次意图，不制造新预约 |
| R1/R3：核对发现预约已保存，通知失败 | 预约已成立与通知待处理分开显示；保留预约结果 | 展示实际契约允许的查询/工作人员处理，不声称真实发出消息 |
| R2：同一提交再试 | 模拟返回同一预约结果，保持对象与结果关联 | 另一次独立意图不能仅因同名被去重；原型行为不是后端幂等证据 |
| R4：取消 | 原型中释放对应演示名额，同时历史仍可识别为已取消 | 权限、未发通知怎样处理、真实跨刷新恢复仍按未知/模拟声明，不自行补规则 |

可观察“是否理解现在预约成立了”及“是否知道怎样核对”，不能把原型数据变化当实际事务、外部幂等或生产恢复已实现。

## 方法来源与证据边界

2026-09-09 的研究核对了 [W3C APG 模态对话框](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)、[文字对比度解释](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[目标尺寸最低项解释](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum) 和 [焦点不被遮挡最低项解释](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html)。这里提供实际核对方法，不复制外部组件；引用解释资料不能替代当前产品的完整合规审查。
