# 报数行与核对结果怎么读

`build` 每次打几行数，`check` 打一份不一致清单。数不是 0 不一定是错——有的是生成器在明说「这里我读不出」，有的要你动手。这份表说每个数是什么意思、该谁做什么。

## `build` 的报数

### 数据库设计那一行

| 报的是 | 意思 | 怎么办 |
|---|---|---|
| 未合并的动态定义 | 建表文件里要到库里运行时才定的改动（`EXECUTE` 拼出来的、循环里的），没并进表结构 | 不用办；页面上那张表顶上有提示。数很大时告诉用户页面上的约束可能与库里不一致 |
| 未解析的语句 | 建表文件里有语句没读懂 | 去首页的清单看原文。是方言或写法生成器不认的，记成 feedback 回流框架；不为了让它读懂去改建表文件 |
| 定义冲突 | 同一张表定义了两次且不一样 | 告诉用户；多半是 `ddl` 里把旧文件也列进来了 |
| 改了不存在的表 | 有 `ALTER` 改的表在前面没建过 | `ddl` 没列全或先后不对，照执行顺序补 |
| 表名运行时拼的 | 代码里的 SQL 表名是拼出来的，不知道写读的是哪张 | 看首页清单；能从代码里确定全集的写进 map.json 的 `dynamicTables`，确定不了的不写 |
| 代码里建的表 | 代码的字符串里有 `CREATE TABLE`，而那个文件没列进 `ddl` | 把那个代码文件加进 `ddl` |
| 没扫成的文件 | 文件里有没闭合的字符串，整个没扫 | 它里面的写读不在任何页面上；多半是代码本身的问题，告诉用户 |
| 项目判断里对不上的 | map.json 里点到了不存在的表 | 改 map.json |
| 说明待更新 | 说明写完之后它依据的那段来源变了 | `pending` 看旧正文，照新来源重写后 `note put` |
| 孤儿 | 说明的锚点已经不存在（表删了、改名了） | 改挂到新锚点，或 `note drop` |

### 架构那两行

| 报的是 | 意思 | 怎么办 |
|---|---|---|
| 按目录分的，还没有项目判断 | 没写 `modules`，按代码根下的一级目录机械分的 | 目录平铺、只分出一两个大模块时提一份划分 |
| 未归属的文件 | 没有模块的 `paths` 匹配到它 | 在 map.json 里归位；它们不进任何模块的依赖 |
| 循环依赖、越层引用 | 照引用关系算出来的事实 | 不是报错。照实上页面，算不算问题由人判断，不为了消掉它去改划分 |
| 项目判断里对不上的 | `modules` 写得对不上：一个文件被两个模块匹配、模块一个文件都没匹配到、层名不在 `layers` 里、id 不合写法 | 首页清单逐条写着，改 map.json |
| 没解析到的引用 | 像是项目里的引用却没对上文件，或者生成器拿不准指的是哪个 | 去首页看每一条的说明；写模块说明时别把它们当成已经连上的依赖 |
| 运行时才定的引用 | 引用的模块名是变量、拼出来的 | 静态看不出，照实列着 |
| 隐去 N 处 | 来源里有形如内网地址、口令、密钥的字样，页面上换掉了 | 首页顶上的清单逐行看：来源里有这些东西，这件事本身要告诉用户 |

接口的完整路径拼不出的，页面上标着原因：「前缀是运行时定的」是路径或前缀不是写死的值；「没找到它挂在哪」是这个路由器没被认得出的挂载点到。两种都不给猜的地址。

## 退出码 3

`build` 退出码 3 是落盘之前被自检拦下，原有页面没动：

- **切块对不上原文**（点名某份文件第几行）：需求规格或旧文档切块丢了字。是生成器的缺陷，把那一行的写法记成 feedback；不为了过自检去改规格的内容。
- **页面读回来与事实对不上**（点名哪一页哪一项）：出页面的代码有错。同样回流框架。
- **页面里有没隐去的敏感字样**：点名哪一页。回流框架；这一版页面不要手工放出去。

## `check` 的不一致清单

| 种类 | 意思 | 怎么办 |
|---|---|---|
| `stale-page` / `missing-page` / `extra-page` | 页面不是现行的：来源、配置、项目判断或说明改了没重出，或者有人手改了页面 | `build` 后提交。超过十张只列前十张——先重出再核对 |
| `fact-mismatch` / `arch-mismatch` | 页面上显示的与重新取的事实对不上 | 刚重出过还报，是出页面的代码有错，回流框架 |
| `note-stale` / `note-orphan` | 说明过期、成了孤儿 | 同上面「待更新」「孤儿」 |
| `note-mismatch` | 页面上的说明与落盘的不一样 | 重出；有人手改了页面或 notes/ 下的文件 |
| `arch-map` | 模块划分写得对不上 | 改 map.json |
| `dangling` | 指向不存在的东西：项目判断里的表、页面里的站内链接 | 改 map.json 或重出 |
| `spec-` 开头的几种 | 需求规格（或旧文档）页面上缺块、多块、字不同、挂的位置不对、图里的字对不上 | 多半是手改了页面，重出 |

没写说明不算不一致，只在摘要里报数。`check` 是 0 条而 `pending` 还有缺口，是「同步但没写全」，不是没同步。

## `init --suggest` 的漏项

配置是什么时候起草的，它就只知道那时候的项目。之后新出现的建表文件、代码目录、需求规格、架构文档，`init --suggest` 报出来，填进 config.json 即可；确实不想让某个目录进文档的，把它写进 `ignore`，就不再报。
