# 设计规范：售后工单派单

> 填充范例（与 product-spec-builder/examples/after-sales-dispatch.md 同一产品）。示范从情境与首要动作起手、surface closure、八态、token 引用不写值、假设与待确认。视觉 token 在同目录 after-sales-dispatch-DESIGN.md。

## 0. AI 使用说明
- 本文档定义界面结构、行为、状态和交互规则；视觉身份在 DESIGN.md。
- Product Spec 是功能范围的事实来源；本文档不新增核心功能。
- 界面型，两端（桌面客服端 / 手机组长与维修工端），§A 标 N/A。
- 优先设计 P0 流程与页面；每页八态；页面、组件与 DESIGN.md token 一致。

## 1. 设计方向

### 1.0 形态与使用情境
| 维度 | 方向 |
|---|---|
| 形态 | 界面型（响应式 Web，两端） |
| 首版基准端 | 两端都是 P0 流程的一环：桌面端录单派单，手机端接单结单；不能只做一端 |
| 使用情境 | 客服：坐工位、双手、一次 1-2 分钟、随时被电话打断。组长：车间、手机单手、几秒钟看一眼派人。维修工：客户家、单手、光线不定 |
| 首要动作 | 客服：「派单」；组长：点人；维修工：拍照结单 |

### 1.1 设计目标
打断后回来接得上，几秒内找到人、拇指够得到——桌面端为「被打断」设计，手机端为「一眼一拇指」设计。

### 1.2 气质与原则
| 维度 | 方向 |
|---|---|
| 情绪词 | 克制、精确、可靠 |
| 具体参照物 | 瑞士手表的说明书：单色为主、结构靠细线、字号差距小、每个符号都有含义。由它推出：不做渐变、不做发光、不做圆润卡片阵列 |
| 信息密度 | 桌面端中等偏紧（待派列表要一屏看全）；手机端宽松（44px 命中区、16px 正文） |
| 大胆放在哪一处 | 只有一处彩色：待派单上的型号标签用 `{colors.primary}`，其余全是墨与纸 |

- DP-1：状态靠形状不靠颜色——待派 / 已派 / 已完成用空心 / 半实 / 实心点，色盲与打印都能读。
- DP-2：一屏一个主动作——桌面端「派单」、手机端「结单」，其它按钮降为次级或藏进菜单。
- DP-3：打断可续——录到一半的单自动存草稿，回来时光标在原处。

### 1.3 参考与反参考
**正向参考**
| 参考产品 | 具体喜欢哪一点 | 承重 |
|---|---|---|
| Linear 的列表页 | 32px 行高、状态点、键盘可全程操作 | Yes |
| 微信「文件传输助手」 | 手机端零学习成本：一列、大点、大字 | Yes |

**反参考**
- 典型 Ant Design 蓝白后台：一律蓝色主按钮、卡片阵列、表格里塞十几列。
- AI 通病清单已过：排除奶油底 + 陶土橙、ALL-CAPS 眉标、按钮尾巴「→」、每段淡入。

## 2. 信息架构

### 2.1 导航结构
桌面端：左侧窄导航（待派 / 全部工单 / 维修工 / 设置），主区右侧。手机端：无导航，打开即当前角色的唯一列表（组长：待派；维修工：我的单）。

### 2.2 页面清单
| 页面编号 | 页面名称 | 页面目的 | 关联流程 / 范围 | 端 | 优先级 |
|---|---|---|---|---|---|
| SCREEN-1 | 录单与待派 | 客服录单、看待派列表与状态 | FLOW-1 / SCOPE-1 / SCOPE-5 | 桌面 | P0 |
| SCREEN-2 | 组长派单 | 按型号列出会修的人，点人派出 | FLOW-1 / FLOW-2 / SCOPE-2 / SCOPE-4 | 手机 | P0 |
| SCREEN-3 | 维修工我的单 | 看单、拍照结单 | FLOW-1 / SCOPE-3 | 手机 | P0 |
| SCREEN-4 | 维修工管理 | 组长维护会修型号与休假 | SCOPE-4 | 桌面 | P1 |

### 2.3 页面关系与 surface closure
主路径：SCREEN-1（录单）→ SCREEN-2（派）→ SCREEN-3（结单）→ SCREEN-1 收到结单提醒。
核对：SCOPE-1 → SCREEN-1；SCOPE-2 → SCREEN-2；SCOPE-3 → SCREEN-3；SCOPE-4 → SCREEN-2 + SCREEN-4；SCOPE-5 → SCREEN-1 筛选。每个页面都有流程落到它。

## 3. 页面规格

### SCREEN-1：录单与待派
**页面目的**：客服录单并看到派单进度，不用翻群。
**首要动作**：「派单」；**次要操作**：作废、筛选、查已完成。
**首屏开在**：左边一张正在录的单，右边待派列表——这个产品世界里最有特征的东西是「正在流动的单子」，不是统计数字。
**布局结构**：
1. 顶部：当前客服姓名、结单提醒角标
2. 主内容区：左 40% 录单表单（6 个字段，型号下拉必填），右 60% 待派 / 已派列表
3. 辅助区：无第二侧栏，筛选放列表顶部一行
4. 底部：无固定区
**内容层级**：
| 优先级 | 元素 | 说明 |
|---|---|---|
| 1 | 「派单」按钮与型号字段 | 录单的终点与最易错的字段 |
| 2 | 待派列表的状态点与维修工名 | 打断回来先看它 |
| 3 | 筛选与已完成 | 低频 |
**使用的组件**：CMP-1 工单行、CMP-2 状态点、CMP-3 主按钮、CMP-4 表单字段
**必需状态**：
- 空：「今天还没有工单。」+ 光标停在客户字段
- 加载：列表骨架屏 5 行镜像行高
- 成功：单子出现在待派列表顶部，状态空心点，行高亮一次即退
- 错误：型号未选 → 字段下方红字「型号必填，客户说不清就选『未知』」，焦点回字段
- 冲突：同一单被组长派出时客服正在改 → 顶部一行「组长已派给小张，你的修改未保存」+ 「查看」
- 离线：列表可看，「派单」变「离线，恢复后自动提交」并排队
- 无权限 / 禁用：维修工账号打开此页 → 跳到 SCREEN-3
- AI 工作中：N/A
**响应式**：桌面 1280 起两栏；笔记本 1024 两栏收窄；<768 单列先表单后列表（客服基本不会用手机，允许）；超宽限 1440。
**可访问性说明**：表单 Tab 顺序即字段顺序；Enter 提交；型号下拉可键盘搜索；状态点配文字。

### SCREEN-2：组长派单
**页面目的**：几秒内把单派给会修的人。
**首要动作**：点人；**次要操作**：改派、看详情。
**首屏开在**：待派单列表，每行大字型号 + 客户区域，点开即会修该型号的人。
**布局结构**：
1. 顶部：待派数
2. 主内容区：一列待派单，点开展开会修该型号的维修工（姓名 + 手上几单），拇指区域
3. 辅助区：无
4. 底部：无
**内容层级**：型号与地址 > 可派的人 > 其它。
**使用的组件**：CMP-1 工单行（手机变体）、CMP-2 状态点、CMP-5 人员选项
**必需状态**：
- 空：「没有待派的单。」
- 加载：3 行骨架
- 成功：点人后该单从列表消失，顶部一行「已派给小张」3 秒
- 错误：会修该型号的人都在外 → 展开区显示「无可派人员」+ 「等待」/「老张（VIP 通道）」
- 冲突：另一位组长同时派了 → 「已被老周派给小张」并刷新
- 离线：列表可看，点人排队并显示「离线，恢复后派出」
- 无权限 / 禁用：非组长打开 → 跳各自页面
- AI 工作中：N/A
**响应式**：只做 360-430 手机；平板按手机拉宽限 600。
**可访问性说明**：人员选项 ≥48dp；状态点配文字；VIP 单有「VIP」文字不是只变色。

### SCREEN-3：维修工我的单
**页面目的**：看单、上门、拍照结单，两步以内。
**首要动作**：拍照结单；**次要操作**：拨打客户电话（Q-2 未定，默认可见）、查看地址。
**首屏开在**：当前要去的那一单，大字地址与型号。
**布局结构**：
1. 顶部：我的待办数
2. 主内容区：当前单卡（单卡不是卡片阵列）：地址、型号、问题、电话按钮
3. 辅助区：无
4. 底部：固定「拍照结单」大按钮，安全区内
**内容层级**：地址与型号 > 结单按钮 > 电话 > 历史。
**使用的组件**：CMP-3 主按钮（手机固定底部变体）、CMP-2 状态点
**必需状态**：
- 空：「暂无派给你的单。」
- 加载：单卡骨架
- 成功：照片缩略图出现，按钮变「已结单」实心点，2 秒后回列表
- 错误：照片上传失败 → 「照片没传上去，重试」保留已拍照片
- 冲突：单已被改派 → 「这单已改派给小张」并退出
- 离线：照片本地暂存，显示「离线，恢复后上传」，结单排队
- 无权限 / 禁用：N/A
- AI 工作中：N/A
**响应式**：只做手机；横屏按钮仍在底部安全区。
**可访问性说明**：结单按钮 ≥56px 高；强光下正文对比 ≥7:1（DESIGN.md on-surface 与 neutral 组合已按此定）。

### SCREEN-4：维修工管理
**页面目的**：组长维护每人会修的型号与休假。
**首要动作**：勾型号；**次要操作**：标休假。
**首屏开在**：人员表。
**布局结构**：主内容区一张表（姓名 / 会修型号 chips / 休假开关），无辅助区。
**内容层级**：会修型号 > 休假 > 其它。
**使用的组件**：CMP-6 型号 chip、CMP-7 开关
**必需状态**：空「还没有维修工，先添加一位」；加载表骨架；成功勾选即存并轻提示；错误保存失败行内提示重试；冲突另一组长改了同一人 → 刷新提示；离线只读；无权限跳转；AI 工作中 N/A。
**响应式**：桌面为主；<768 表变卡片列表。
**可访问性说明**：chip 可键盘勾选，开关有文字状态。

## 4. 组件规格
> UI 系统继承：shadcn/ui（Next.js + Tailwind），只写差量；视觉值引用 DESIGN.md components token。

### CMP-1：工单行
**组件用途**：列表里一条工单，桌面与手机两种密度；**使用位置**：SCREEN-1、SCREEN-2、SCREEN-3
**变体**：桌面（32px 行高）/ 手机（56px 行高，拇指可点）
**状态**：默认 `{components.row}`；悬停背景变 `{colors.surface}` 不位移；聚焦焦点环；激活当前行左侧墨线；禁用（作废单）文字 `{colors.on-surface-muted}` + 删除线；加载骨架；错误行尾红字。
**内容规则**：型号在前、地址其次、状态点带文字；不显示客户电话（可见性 Q-2）。
**可访问性要求**：整行可键盘聚焦，Enter 展开；状态文字非仅颜色。

### CMP-2：状态点
**组件用途**：待派 / 已派 / 已完成 / 作废 / VIP；**使用位置**：全部列表
**变体**：空心（待派）/ 半实（已派）/ 实心（已完成）/ 删除线（作废）/ 双环（VIP）
**状态**：语义全靠形状；颜色只在已完成用 `{colors.success}`、作废用 `{colors.error}` 做冗余通道。
**内容规则**：点旁必有文字。
**可访问性要求**：`aria-label` 带状态名。

### CMP-3：主按钮
**组件用途**：每屏唯一主动作；**使用位置**：SCREEN-1「派单」、SCREEN-3「拍照结单」
**变体**：桌面（`{components.button-primary}`）/ 手机固定底部（全宽，高 56px，安全区内）
**状态**：默认 / 悬停 `{components.button-primary-hover}` 不位移 / 聚焦焦点环 / 禁用 40% 不透明度 / 加载「派单中…」保留文案 + 进度 / 错误恢复可用。
**内容规则**：动词说清结果：「派单」「拍照结单」，不用「提交」「确定」。
**可访问性要求**：命中区 ≥44px；加载时 `aria-busy`。

### CMP-4 表单字段 / CMP-5 人员选项 / CMP-6 型号 chip / CMP-7 开关
继承 shadcn 默认，差量：字段高 ≥44px（手机）、label 常显不用 placeholder 替代；人员选项一行「姓名 · 手上 2 单」高 56px；chip 选中实心未选空心；开关带文字「休假中」。

## 5. 交互与反馈规则
### 5.1 交互原语
| 模式 | 规则 |
|---|---|
| 主操作 | 每屏一个：桌面右下角「派单」，手机固定底部；其它按钮次级 |
| 次要操作 | 行内文字按钮或行尾菜单 |
| 危险操作 | 作废需确认弹层（一层），并给 10 秒撤销 |
| 保存行为 | 录单自动存草稿；离开前未保存提示 |
| 导航 | 筛选与 Tab 进 URL，可深链；后退恢复滚动 |
| 弹窗 / 抽屉 | 只用于作废确认与详情；不叠层 |
| 键盘 | 桌面端：Tab 顺序即字段顺序，Enter 派单，`/` 聚焦搜索 |

### 5.2 反馈规则
| 场景 | UI 反馈 | 文案规则 |
|---|---|---|
| 成功 | 行高亮一次 + 顶部一行 3 秒 | 「已派给小张」直接陈述 |
| 错误 | 字段下方或行尾红字，焦点回去 | 出了什么 + 下一步：「型号必填，说不清选『未知』」 |
| 警告 | 顶部一行黄底 | 「离线，恢复后自动提交」 |
| 空状态 | 一句 + 下一步 | 「今天还没有工单。」 |
| 加载 | 骨架镜像 | 「派单中…」 |

### 5.3 动效规则
- 只留一处编排好的时刻：新单进入待派列表时的一次高亮渐退（`{motion.content}`）。
- 其余只响应用户动作：展开人员列表、按钮按压（缩放 0.98）；无页面级转场；reduced-motion 全部归零。

## 6. 文案
- 语气：清晰、直接，面向一线；不卖萌不道歉。
- 按钮：「派单」「拍照结单」「作废」；同一动作全程同名（按钮「派单」→ 提示「已派给…」）。
- 表单：label 常显；placeholder 给示例「如 X-200」；error 说原因 + 怎么改。
- 空态：一句原因 + 下一步。
- 术语：与 Spec 一致——「待派 / 已派 / 已完成 / 作废」，不出现「处理中」。

## 7. 可访问性与响应式
- 目标：WCAG 2.2 AA；手机端正文对比 ≥7:1（户外）。
- 必需规则：键盘可达、焦点可见、字段有 label、错误关联字段、不只靠颜色、图标有文字、标题层级、reduced-motion。
- 断点：| 手机 360-430 | 平板 600-1023（按手机拉宽） | 桌面 1024-1439 | 超宽限 1440 |

### 9.2 待确认问题
| 编号 | 问题 | 是否阻塞 | 谁能答 | 不答先按什么做 |
|---|---|---|---|---|
| DQ-1 | 维修工端要不要显示客户电话（对应 Spec Q-2） | No | 用户 | 显示，可由客服关闭 |
| DQ-2 | 待派列表默认按时间还是按型号分组 | No | 组长 | 按时间，型号可筛 |
