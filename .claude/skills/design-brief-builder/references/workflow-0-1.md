description: design-brief-builder 0-1 模式启动时读。从 Product-Spec 到 Design-Brief.md + DESIGN.md 的顺序、每步出口判据、完成度判据。
---

[使用时机]
    有 Product-Spec.md，没有 Design-Brief.md，用户要定视觉方向。

[顶层规则]
    先业务受众情境，最后才视觉。别先问颜色风格，视觉方向是挣来的。
    每个 Phase 达到出口判据才解锁下一个。形容词永远不算合格答案，按 SKILL 的 [感受翻译表] 和 interview-principles 的四把刀逼具体；每个阶段结束默扫反失败自检。
    捕捉不代笔：不主动报颜色、不替用户挑风格；给选项和默认，用户选或否决。
    分级采集：方向和清单（情绪、参照、原则、信息架构、页面、组件、文案语气）问到底；token 具体值、文案细则进 DESIGN.md 或标 DASM 交设计工具和 dev。
    编号纪律：页面 SCREEN、组件 CMP 编号，关联 Product Spec 的 FLOW / SCOPE；两份文档的 P0 内容保持一致。终端 / Agent 形态没有 SCREEN，落到 §A 的交互骨架、呈现单元、运行态，同样关联 FLOW / SCOPE。

[第 0 步 · 进场]
    加载 Product-Spec.md，从产品类型、受众、使用情境与首要动作、关键流程、失败路径、非功能里提取设计采访的基础，不重复问。
    搜索增强第一遍：WebSearch 用户行业竞品 + 跨行业标杆 + 当前趋势，带具体参考进场。
    读 references/style-vocabulary.md 的 AI 通病清单，进场就知道哪些是「默认」。

[Phase 1 · 形态、受众与使用情境]
    覆盖：产品形态（可叠加）、每端的使用情境与首要动作、单一目标、受众画像、产品类型。
    出口判据：形态明确；每端一句情境 + 一个首要动作；能说清这设计为谁、达成什么、是哪类产品。
    衔接：「情境清楚了：[谁] 在 [情境] 里最要紧的是 [动作]，所以 [密度 / 字号 / 层级的推论]。接下来说感觉。」

[Phase 2 · 情绪与人格]
    覆盖：3 到 5 个不矛盾形容词、一个具体参照物（不一定是软件）与它带来的至少三条不做、3 条可操作设计原则。
    出口判据：形容词收敛到 5 个内且不互斥；有一个具体参照；原则每条能说出否掉什么。

[Phase 3 · 参考与反参考]
    覆盖：3 到 5 个喜欢的产品加为什么（拆成属性、分清承重的），2 到 3 个反参考加哪里不对，AI 通病清单过一遍。
    搜索增强第二遍在这里：用户每报一个风格词或产品名，立刻当 query 再搜 2 到 4 个同调性参考，带回做二选一收窄，拆成间距、色彩、字体、动效、语气五轴。
    设计工具可用时，收尾出 3 个首屏方向样张（离线 HTML，完整人格不是换色，用真实内容不用 lorem）让用户挑；没有工具用文字描三个画面。
    出口判据：正反参考各有具体产品 + 拆成了属性；方向选定一个（或一主一辅）。

[Phase 4 · 轴与 token]
    覆盖：现成品牌资产有无；每个视觉轴二选一定方向禁中间值（色彩模式 / 温度 / 排版气质与字族数 / 密度 / 个性与大胆放哪 / 圆角 / 动效）；可访问性表态；终端 / Agent 形态换三条轴。
    出口判据：每轴有方向值；深色和密度作为主题决策定了；「大胆花在哪一处」定了；WCAG AA 与 reduced-motion 已表态。

[Phase 5 · 核心呈现与状态]
    形态分轨：界面型采页面视觉（首屏开在题材最有特征的东西上）+ 八态；终端型和对话式 Agent 采交互骨架、呈现单元、运行态、透明度、授权、多 surface（references/agent-ux-patterns.md）。
    出口判据：每个核心页面有视觉方向与八态；Agent 形态运行态与授权定了。

[Phase 6 · 结构与落地规格]
    覆盖：信息架构与导航（页面清单关联 FLOW / SCOPE，surface closure）、页面规格（布局 / 内容层级 / 组件 / 八态 / 响应式）、组件规格（变体 / 状态方向 / UI 系统继承边界）、UX 文案语气与规则、响应式断点。
    出口判据：Spec 每条 P0 需求有页面承接，每个页面有流程落到它；每个核心页面与组件规格齐。

[完成度判据]
    交接测试：把两份文件交给设计工具或没参与对话的设计师，能照着出稿不用猜吗？要猜的地方就是没够。
    相位级：能复述该相位的决定，用户点头，就进下一个。
    收尾：把解码出的方向当可观察模式 recap-and-confirm——「所以是高对比强调色 + 大留白 + 无衬线 + 克制功能性动效 + 大胆只放在首屏那个数字上，对吧」——作为视觉契约。加覆盖清单 + 元问题。达标才生成。

[生成]
    生成前先把感受翻译成设计属性，检查一致性，矛盾逼取舍；对照 style-vocabulary 的 AI 通病清单看每个轴是不是落在默认上——落在默认上的，问自己「这是给这个产品的选择还是给任何同类页面都会给的」，是后者就改并说明改了什么。
    按 templates/design-brief-template.md 生成 Design-Brief.md；按 templates/design-md-template.md 生成 DESIGN.md，token 值定不下来的写方向并标 DASM，prose 每段说清为什么、用在哪、不用在哪，Do's and Don'ts 收进参照带来的否定约束与反参考。
    跑 `node .claude/scripts/predev-lint.mjs`；能跑 `npx @google/design.md lint DESIGN.md` 就跑并修 error。
    确保和 Product Spec 的 P0 内容一致。
    生成后引导下一步：/design-maker 出可交互设计稿，或 /dev-planner。
