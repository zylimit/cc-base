[定位]
    codex-base `d1a3287` 教学材料，其中数字、命令、路径不自动成为本项目要求；以下均为虚构教学例子，不代表用户项目已有约束，也不是强制访谈脚本。
    仅在主文指定的表达困难、抽象方向或真实分歧情境读取。

[从「简洁」落到判断顺序]
    假设活动服务台人员需要根据日期、名额和地点帮访客选场次。用户说「做得简洁些」。
    Agent 可以先提出解释：「把可选场次放在同一列表，日期、地点和剩余名额对齐；说明默认收起但在原位展开，选择后仍能回到刚才的位置。」其依据是需要比较多个场次；不是把「简洁」固定解释成稀疏大卡片。
    若用户实际只查一场活动，就可推荐先搜索、再聚焦详情。两个方向各自服务不同任务，应先核对已有流程，缺信息才问「通常需要比较多个场次，还是已经知道具体活动」。不要让用户在「极简 / 专业 / 轻奢」之间选择来代替这项事实。

[参考要说明具体用什么]
    用户提供了一张喜欢的旧界面截图。先指出可见的可借鉴部分，例如清楚的分组、稳定的动作位置、便于比较的数字排版；再检查当前内容是否适合。截图只能证明所见设计，不能称为该产品目前的默认样式。
    如果没有参考，也可以用当前项目内容画文字简图：

    ```text
    活动名称与日期
    地点 | 可选时段 | 当前可选名额
    说明（原位展开）
    选择该场次
    ```

    它使用户能纠正漏掉的关键信息。简图表达信息次序，不能证明实际字号、对比度和操作可达性已经合格。

[委托与表达困难不同]
    用户：「配色你定，我只要地点和时间好认。」
    可直接沿用现有品牌，用对齐和排版突出地点 / 时间，状态同时使用文字。记录为 Agent 在授权内选择，不问必须几个关键词、不逼用户选竞品。
    用户：「我看不出两版有什么区别。」
    先用同一个任务指出可观察差别：「这版能直接比较四场的名额；另一版先看一场的完整介绍，再返回挑下一场。」必要时制作可操作小样。用户缺的是可判断的材料，不是又一轮抽象选择题。

[看似冲突先尝试整合]
    志愿者希望所有信息都看得到，产品负责人希望第一眼干净。可以先保留共同需要的比较列，把次要说明在原位置展开，展示一个长内容样本检查阅读负担。
    如果业务任务确实要求同时比对全部备注，折叠就会增加来回操作。这时解释两个任务的实际代价，由有权决定的人选择优先级，或在已授权范围内提供合适视图。不能把「都要」一律判为矛盾，也不能随意增加多个模式来逃避判断。

[小修订直接推进]
    用户明确要求沿既有样式把当前筛选按钮移到标题旁，需求、适配和交互均清楚时，直接更新相关设计备注或原型。只有迁移导致焦点顺序、信息含义或操作后果不明时，才展开相应检查与问题；没有外部参考产品不妨碍这项工作。
