[定位]
    codex-base `d1a3287` 教学材料；预约例是虚构案例，其中数字、命令、路径不自动成为本项目要求。
    当形态选择、视觉方向或构成仍影响当前任务时读取相关部分。已定方向的局部修改直接继承。设计者应提出有依据的具体建议，以下方法不要求业务人员填色值、选字体或参加固定轮数的方案评选。

[先辨认实际表面]
    | 表面 | 优先学习什么 | 设计动作与退出条件 |
    |---|---|---|
    | GUI | 比较还是逐项操作、输入设备、窗口 / 屏幕、已有导航 | 先画内容与动作关系，再选密度和组件；当前任务能走通即可继续，不补全产品所有页面 |
    | 终端 | 交互还是流水线、列宽、长路径、颜色支持、输出是否供脚本读取 | 优先稳定列与层次、无色含义、可复制内容；机器输出契约与人读样式分开，不把表格颜色当唯一状态 |
    | 对话 | 一轮要作什么判断、哪些上下文必须可见、结果落到哪里 | 用可扫读的结果摘要和明确下一步，保留原结果与必要来源；不把冗长聊天或隐藏思维链当进度 |
    | 嵌入区域 | 宿主空间、已有组件、焦点 / 滚动、输入冲突 | 先核对能改的区域与必须保留的宿主行为；不要为一块面板接管整页或复制宿主导航 |
    | 组合 | 各表面分别承担哪段任务、状态怎样延续 | 保持对象、结果和动作含义一致，允许布局不同；确有切换需求才设计跨表面恢复，不新增未经要求的客户端 |
    这些是界面语境，不是质量等级。未知宿主能力先核对实际文档 / 工具；形态清楚就不再询问。

[用实际内容建立画面骨架]
    选最影响当前判断的一屏或一段任务。先放入真实或明确标注为虚构的代表内容，至少让当前有风险的长标题、混合文字 / 数字 / 单位、空值、说明和状态有机会出现；不是为所有页面凑测试数据。
    沿「第一眼找对象 → 比较决定因素 → 识别动作 → 判断动作结果」安排内容。把主内容与辅助解释分清，但不要自动隐藏用户决策所必需的信息。资料没有说明重要性时，用真实任务验证：「作出这个决定之前还缺什么」，不要问喜欢卡片还是表格代替业务取证。
    画面骨架先确定对齐、分组、主次与动作位置。去掉颜色和装饰后仍应可理解基本关系；这只是信息层次自检，不说明实际可访问性已通过。

[按当前问题研究参考]
    先检查项目品牌、token、组件及实际使用中的页面，区分必须继承与可以改变的部分。只有它们不足以回答当前设计问题，或用户明确要求研究方向时，再看外部参考。
    选择参考依据是任务与约束，例如密集记录如何比较、主动作如何辨认、媒体背景上的控件如何保持可读。打开相关界面或原图，记录看到的具体部分；只有产品宣传文字不能证明画面实际表现。
    参考记录可用短表，按实际数量填写：
    | 定位与时间 | 实际观察 | 借鉴与转译 | 不借 / 未验证 |
    |---|---|---|---|
    | URL 或项目文件、版本 / 访问日期 | 所见画面的层次、密度或反馈 | 本项目哪项内容 / 动作因此改变 | 任务、平台、数据或授权差异；没看过的状态 |
    许可与资产使用另行判断；可以讨论方法，不代表可以复制图、字体或代码。未知许可不把外部资产放进交付物。生成插图也先说明它服务什么内容与动作；现有图标体系能表达时优先沿用。

[怎样选择具体构成]
    | 构成 | 从什么证据作判断 | 具体设计动作 | 需要反查的失效 |
    |---|---|---|---|
    | 排版与阅读节奏 | 视距、连续阅读 / 快速扫描、中文与数字比例、已有字体 | 先选可读的正文，再拉开标题 / 分组 / 标签层级；同类数字对齐、单位贴近数值；用行长和行距控制阅读，不靠把所有次要字缩小 | 长标题把动作挤走、说明过淡、数字单位断开、系统字体回退后溢出 |
    | 密度 | 必须同时比较的信息、使用频率、触控与键盘需求 | 密集任务用稳定对齐与明确分组；低频单次任务允许更聚焦的内容块；将不同任务的密度分开解释 | 过密导致误点，过疏导致来回滚动才能比较；隐藏字段是否增加记忆负担 |
    | 留白与分组 | 哪些内容属于同一对象、哪些是下一项工作 | 组内距离小于组间距离，用一致的节奏区分层级；把主要动作与危险 / 辅助动作拉开关系 | 等距排布抹平关系、过大空白把状态与对象分离、边框层层嵌套产生噪音 |
    | 语义色与强调 | 品牌约束、业务状态、选择、键盘焦点 | 先定义颜色角色，再选具体值；主动作只在需要时突出；成功 / 失败 / 未知加文字或形状，选择与焦点可以同时辨认 | 把通知失败染成整个预约失败；黄色同时代表选中与告警；占位文字或弱状态难读 |
    | 图像与图标 | 需要识别实物、解释流程还是建立气氛，内容 / 授权是否可得 | 用能帮助判断的图；装饰控制面积；图标沿已有语言，含义不明的动作保留标签；必要时用图注 / 替代文本承接内容 | 装饰抢走任务焦点、图标猜不出动作、裁切丢关键内容、图片加载成为唯一信息来源 |
    | 材料与空间层次 | 内容层与导航 / 操作层的关系、背景复杂度、平台能力 | 用表面、边线、轻重变化先建立层次；透明 / 模糊只在确需看到背景关系时采用，并准备足够不透明的替代 | 毛玻璃铺满内容、对比随背景波动、卡片与弹层层级不清、性能或 reduced-transparency 条件不适配 |
    | 动效 | 用户是否需要定位新增 / 移除、理解空间变化、知道动作发生 | 动画服务一次状态变化，保留稳定结束态；可中止的工作仍提供清晰控制；reduced-motion 下用即时状态 / 非运动提示 | 反复装饰分散注意、动画延后可用动作、用持续转圈掩盖未知、取消动画被误解成取消真实业务动作 |
    具体字号、间距、颜色与时长由设计者在已有约束内选，并在样张中验证；没有一种固定比例、深色主题或大圆角适合所有任务。更鲜艳或更透明不是「时尚」的验收条件，形成清楚、有节奏、有一致语义的画面才有可讨论的依据。

[同内容比较，再有条件地选择]
    方向未定而且比较能改变判断时，用相同对象、文本长度、数据、状态和主要动作制作可见候选，说明当前主要比较哪个变量。例如比较同时对照与逐条聚焦时，不让其中一版少一半必要信息来制造优势。
    文字简图可先排除错误的信息次序；评价真实字重、留白、对比或材料时，要给实际可见的关键屏小样。没有渲染工具时交待视觉层尚未核验，继续形成结构与明确的设计建议，不把简图当视觉验收。
    带着同一个任务观察每版：先看到什么、找哪个信息、多少来回、结果如何理解。给推荐、依据与代价；用户已委托就采用可逆建议，并留下会触发调整的观察。重要业务含义冲突交主 Agent 补足；用户无需在术语、品牌词或多个参考产品中做无意义选择。

    **同一个管理员任务的两个构图候选**
    承接 [预约教学事实](../../product-spec-builder/references/reservation-case.md)，用虚构名单完成同一个任务：「辨认预约已成立但通知仍需处理的记录，并比较对应场次。」两版都保留姓名、场次、预约状态、通知状态与已有查看动作，不添加功能。以下只比较结构，不是完成渲染的样张或已运行结果。

    ```text
    A：二维对照
    预约者   场次          预约状态   通知状态    动作
    小安     周日·下午场   已成立     发送失败    查看
    小安     周日·上午场   已成立     待发送      查看

    B：逐条归组
    小安                          查看
    场次：周日·下午场
    预约状态：已成立   通知状态：发送失败
    ──────────────────────────────
    小安                          查看
    场次：周日·上午场
    预约状态：已成立   通知状态：待发送
    ```

    在这项密集比较任务下，可先推荐 A：用固定列对齐场次与状态，行内保持紧凑、行间有足够分隔，列头与正文保持清楚层级，通知问题用文字加局部强调，不把整行预约标成失败。B 以对象名称和组间留白建立节奏，更容易逐条阅读，但跨记录比较时眼睛需要上下寻找同一字段。两版的判断依据是内容关系和阅读动作，不是给 A 配更好看的颜色。
    推荐可被推翻：若在实际屏宽 / 长内容下 A 需要反复横向滚动，或任务观察发现跨行错配状态，而 B 能保持字段关联且不妨碍比较，应调整分组、排版或采用 B。尚未观察时这只是有条件的设计判断；不能宣称 A 更快或 B 减少了错误。

[贯穿例：两种密度，同一种结果含义]
    先读 [预约教学事实](../../product-spec-builder/references/reservation-case.md)。以下仅是结构示意，字体、材料、颜色还需真实渲染，不是用户观察或视觉通过结果。
    管理员需要比较记录，可推荐在已有名单中对齐场次、预约状态和通知状态；手机查看自己预约时，可推荐聚焦单条结果。不同密度来自任务与屏幕，不改变 R1–R4。不得因两个角色而自动新建管理后台或增设设置中心。

    ```text
    名单中的同一记录
    场次                预约状态     通知状态      已允许的动作
    周日 · 下午场        已成立       发送失败      查看

    手机中的同一记录
    周日 · 下午场
    预约已成立
    通知发送失败；预约仍有效
    [查看预约]
    ```

    「查看」只是教学动作示意，实际项目需要有已确认入口。将整个卡片变红、只留下「失败」，会让通知状态覆盖预约事实；应在层次上保持结果与问题的归属，不能用全局警报色省略含义。
    R1 的另一种情境是提交未收到回应，此时没有依据显示「已成立」：

    ```text
    正在核对预约结果
    这次提交还没有获得确认，当前不能判断是否成立。
    所选场次与已填内容仍保留。
    [核对本次结果]  （仅当实际契约支持）
    ```

    核对动作仍针对同一提交意图。多久显示升级提示、能否离开后继续、人工介入入口均须承接实际规则；未知时可以留为讨论中的局部，不编造倒计时或「再预约一次」。

[方法来源与边界]
    以下页面在 2026-09-09 的研究中核对，只引用方法，不复制图片 / 代码或宣称本项目获得相同效果。涉及当前平台能力或最新样式时需重新核验。
    - [Design Council 的创新框架](https://www.designcouncil.org.uk/resources/framework-for-innovation/)：采用围绕问题探索和收敛的方法；不规定每个任务固定做两版或走完四个闸门。
    - [Google 的 Material 表达设计研究](https://design.google/library/expressive-material-design-google-research)：借鉴以大小、颜色、形状、位置等组织注意层级，并检查移除标签、打乱熟悉结构的代价；不把其研究数字当当前产品的测量。
    - [Apple 的 Materials 指南](https://developer.apple.com/design/human-interface-guidelines/materials)：借鉴内容层与功能层的材料选择，以及背景、对比和透明适配；不把某个平台材料铺成所有网页的统一皮肤。
